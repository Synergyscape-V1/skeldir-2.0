### 3.2 Authority binding and legal transition enforcement

- Investigation runtime mutations bind to `InvestigationService`.
- Budget runtime mutations bind to `BudgetJobService`.
- Added retry transition helpers:
  - `InvestigationService.request_retry(...)`
  - `BudgetJobService.request_retry(...)`
- Invalid predecessor transitions return conflict problem details (`INVALID_STATE_TRANSITION`).

### 3.3 Postgres-native idempotent replay and audit trail

Added `backend/app/services/review_mutation_ledger.py`:

- Uses `compliance_audit_ledger` as append-only replay/mutation ledger.
- Stores scoped key: `b15:{domain}:{entity_id}:{action}:{idempotency_key}`.
- Replays same-key/same-selector mutation responses with `X-Idempotency-Replayed`.
- Rejects same-key/different-selector misuse with `IDEMPOTENCY_KEY_CONFLICT`.

Persisted mutation metadata:

- actor (`AuthContext.user_id`)
- timestamp (`occurred_at`)
- correlation ID
- mutation intent/action
- idempotency key (scoped/public)

### 3.4 Strict runtime boundary validation

- Launch/mutation request models in both routers now enforce `extra="forbid"`.
- Undeclared authority-boundary fields are rejected at runtime.

### 3.5 Lightweight polling implementation discipline

- Added projection reads:
  - `InvestigationService.get_status_projection(...)`
  - `BudgetJobService.get_status_projection(...)`
- Status handlers use projection queries rather than full result-hydration.
