## 3. Remediations, by causal property

### 3.1 The artifact resolves the governed topology

`B24_PYMC_CHAINS` is **removed** from `backend/Dockerfile.bayesian` rather than
set to `4`. A literal in an image that must agree with a policy in a module is
the same defect with a different value; the next divergence would simply be a
different number. With the override gone, the image inherits the governed
default, and the binding below refuses anything that disagrees.

The `B24_PYMC_CORES` and `B24_BLAS_TOTAL_THREADS` pins stay. Those genuinely are
container-level thread controls that must be set before the process starts. Chain
count is not a thread control — it does not appear in the runtime module's own
budget arithmetic (`worker_concurrency × pymc_cores × blas_total_threads`) — and
that conflation is what F-11 was.

### 3.2 The profile validates the runtime, not its own defaults

`assert_runtime_matches_profile()` compares the **resolved** `B24RuntimePolicy`
against the authorised profile immediately before consequence-bearing sampling,
and returns the correspondence record so callers persist the equality rather than
assert it and discard it.

It covers every dimension a deployment can set:

```
chains          cores           blas_cores
sampler supervisor deadline     celery soft limit      celery hard limit
```

Deliberately not a special case for `B24_PYMC_CHAINS`. The three deadlines are
equally environment-driven and today merely happen to agree with the profile;
C10-09 exists because equality of defaults is not a binding.

Mismatch raises before PyMC is reached. Not "run under the wrong topology and
let diagnostics notice later".

### 3.3 Evidence is observed, not intended

`sampler_child.py` reads the posterior it actually produced:

```python
observed_chains = int(trace.posterior.sizes["chain"])
observed_draws_per_chain = int(trace.posterior.sizes["draw"])
```

`n_chains` and `n_samples_actual` are those measurements.
`authorized_chains` and `authorized_posterior_draws_total` are persisted beside
them, because *what was supposed to happen* and *what actually happened* are
different questions and the defect was answering the second with the first.

`assert_observed_topology_matches_profile()` refuses a posterior whose shape is
not the authorised shape — including the partial-posterior cases the directive
names (3 chains where 4 were authorised, fewer draws than authorised), which the
pre-flight agreement check structurally cannot catch.

### 3.4 The producing regime is durable, immutable, and signed

P5 gains `b24-p5-runtime-policy-v1`, versioning the containment *semantics* —
chain topology, process cage, deadline hierarchy — and not deployment
particulars like hostname, PID or build timestamp, which are audit metadata and
do not change what a confidence means.

The profile binds all four identities and reduces them to one
`policy_bundle_hash`. Four version strings that must be read together are more
faithfully carried as one digest that cannot be half-right than as four fields
that can drift apart or be partially copied.

That bundle is stamped at claim time, carried through execution, persisted on
the fit, selected by Trust's read model, and included in the canonical bytes that
get signed. The database refuses a usable confidence bucket without it, the
terminal-immutability trigger covers it, and a separate write-authority trigger
requires a live dispatch fence to change it.

Trust still computes nothing. It reads persisted authority, as P12 requires.

### 3.5 Fresh dispatch has a production publisher

`publish_due_dispatch_rows_sync()` and the
`app.tasks.bayesian.publish_due_fit_dispatches` task carry a freshly claimed
outbox row onto the real broker, on a Beat schedule that runs with the planner
that created the work.

The SQL is shared with the async path rather than rewritten, so the two cannot
drift into different semantics. Task name, queue, payload shape and capability
semantics are identical to the recovery republisher — the only differences are
which rows are eligible and the assignment reason recorded. What crosses the
broker still authorises nothing: the worker must lease the row against a live
worker generation, and the C5 fence refuses it otherwise.

An RLS policy was required for this to work at all. The publisher is global by
design, like the recovery reconciler, and under `FORCE` RLS a correctly scheduled
publisher would otherwise have observed an empty table and fresh work would still
never have moved.

### 3.6 A fit executes under exactly one regime

Claim time stamps the bundle. A non-terminal re-observation re-stamps it, because
a re-claim happens under today's policy — and that same path refreshes the budget
columns, which is C10-08's fix: without it a fit queued under the old policy was
refused `policy_rejected` forever.

At execution, a not-yet-started, non-terminal fit whose bundle differs is
**replanned** onto the executing regime before any compute, recording
`superseded_policy_bundle_hash`, `policy_replanned_at` and a replan count. A fit
that cannot be replanned — already terminal, or already sampling — is refused
rather than executed.

Replan rather than terminal refusal, deliberately: a terminal `failed` fit is
*reused* on re-observation rather than re-dispatched, so refusing would have
stranded that snapshot's confidence permanently. That is not the directive's
"superseded" outcome; it is a new defect wearing its name.

## 8. What is not claimed

- **The posterior is accepted, not endorsed.** The artifact gate proves the
  topology is what was authorised and that this model converges under it with
  margin. Whether any *particular* production posterior converges stays an
  empirical question the diagnostics answer at runtime.
- **The model itself is unchanged and is not claimed to be adequate.** It remains
  a one-parameter Normal mean. C10 is an authority-binding remediation, as the
  directive states; it is not a statistical-model redesign.
- **The 240/270/300-second envelope is proven sufficient for this model**, at
  roughly five seconds. A larger model would require the profile revalidated —
  which is now a mechanical operation with a gate behind it rather than a
  judgement call.
- **`total_chain_iterations` is not validated against `MAX_P6_SAMPLES`.** The
  validator checks `posterior_draws_total` against that cap and not the
  tuning-inclusive figure. No caller can currently reach the gap —
  `DEFAULT_P6_SAMPLING_POLICY` is a module-level singleton with literal draws and
  tuning — so it is recorded as hardening debt, exactly as the directive's
  classification rule directs, rather than inflated into a C10 blocker.
- **Historical freshness at the envelope level (C9-L) remains unassembled.** It
  is exercised at the database tier by existing proofs and is not composed as an
  end-to-end journey. Unchanged from Corrective IX, and still disclosed rather
  than papered over.
- **Audit 47's Gates 3, 4 and 5 are not refuted, because there is nothing to
  refute.** They analyse files that do not exist. No conclusion is drawn from
  them in either direction.
