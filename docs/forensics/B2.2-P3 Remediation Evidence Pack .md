# B2.2-P3 Remediation Evidence Pack

Date: 2026-04-20  
Branch basis: `main` (post-PR-364)  
Directive: follow-up corrective remediation for DB-native fail-close and production-path purity

## 1) Initial corrective findings

- Canonical substrate semantics were already largely correct (typed provider-preserving envelope, first-class verified ingress state, explicit `verified_at`, strict `event_id` anchor, fixed money exponent authority).
- The remaining blocker was structural: `backend/app/ingestion/event_service.py` still executed request-time `information_schema.tables` introspection via `_webhook_identity_table_available()` on the authoritative webhook path.
- Authoritative fail-close behavior depended on preflight schema probing and test-mode branching (`_testing_mode_enabled()` / `_authoritative_db_proofs_required()`) instead of pure DB-native insert physics.
- `verified_at` was application-assigned in envelope assembly, but capture semantics were not pinned to the verification decision point.

## 2) Corrective remediations implemented

- Replaced schema-probe gate with DB-native authoritative fail-close in `backend/app/ingestion/event_service.py`:
  - Removed `_webhook_identity_table_available()` and all `information_schema.tables` probing from ingress.
  - Removed production ingress test-mode branching (`_testing_mode_enabled`, `_authoritative_db_proofs_required`).
  - Always stages canonical `WebhookIngressIdentity` when required envelope fields are present.
  - Added `_is_missing_webhook_identity_relation_error()` + SQLSTATE handling (`42P01`) and translates missing relation on flush to `AuthoritativeIngressInvariantError`.
- Pinned `verified_at` capture to verification acceptance in `backend/app/api/webhooks.py`:
  - `_authorize_webhook_request()` now stamps `tenant_info["verified_at"]` at auth success.
  - `_handle_ingestion(...)` now requires `verified_at` and threads it unchanged into event payload.
  - Stripe v2 path includes the same propagated `verified_at` semantics.
- Enforced unchanged propagation in `backend/app/ingestion/event_service.py`:
  - `verified_at` is now a required envelope field.
  - `_extract_webhook_ingress_identity()` validates datetime type and propagates the supplied value unchanged.
- Strengthened governance/enforcement surface:
  - Contract bumped to `1.2.0` and now codifies DB-native fail-close authority, no hot-path schema introspection, no production test-branching, and verification-point timestamp capture semantics.
  - Enforcer updated with forbidden-token checks for schema probes/testing branches and required-token checks for verification-point `verified_at` propagation.
