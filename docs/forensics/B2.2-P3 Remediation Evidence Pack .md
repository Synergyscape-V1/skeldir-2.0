## 1) Initial corrective findings

- The canonical identity envelope substrate existed but authoritative write-path semantics were weaker than phase law.
- `backend/app/ingestion/event_service.py` allowed envelope persistence bypass via `_webhook_identity_table_available()` gating.
- Verified ingress truth had no dedicated domain-time field; envelope rows depended on generic lifecycle timestamps.
- Ledger anchoring was present via FK but not strictly one-to-one by `event_id`.

## 2) Corrective remediations implemented

- Authoritative substrate enforcement hardened in `backend/app/ingestion/event_service.py`:
  - Introduced `AuthoritativeIngressInvariantError`.
  - Removed silent write bypass from the canonical insert path.
  - Added explicit substrate assertion before envelope persistence (`_assert_webhook_identity_substrate_available`).
  - Added strict failure when authoritative ingress state exists but canonical envelope fields are absent.
  - Preserved non-authoritative migration/test ergonomics only in explicit testing mode without DB-proof requirement.
- Added dedicated domain time semantics:
  - New first-class `verified_at` field in `WebhookIngressIdentity` model.
  - Migration + canonical schema include `verified_at timestamptz not null default now()`.
- Strengthened ledger anchoring:
  - Added strict unique anchor on `event_id` (`uq_webhook_ingress_identities_event_id`) alongside FK to `attribution_events(id) on delete cascade`.
- Formalized fixed exponent authority:
  - Added `_FIXED_MONEY_EXPONENT_BY_CURRENCY` and `_canonical_money_scale()` in `backend/app/api/webhooks.py`.
  - Replaced per-handler hardcoded scale literals with fixed local authority resolution.
- Strengthened governance/evidence CI surface:
  - Contract bumped to `1.1.0` with `verified_at`, fixed exponent authority declaration, and required ledger anchor declaration.
  - Enforcer expanded to assert new invariants in model/migration/webhooks/event-service/test surfaces.
  - Runtime proof suite extended with substrate-absence failure test and `verified_at`/event-anchor assertions.
