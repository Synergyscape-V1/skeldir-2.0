# B2.4-P5 Remediation Evidence Pack

## Scope

B2.4-P5 is a bounded Bayesian runtime harness. It proves that PyMC/PyTensor/ArviZ can run in an isolated worker lane with native thread caps, PyTensor compiledir isolation, process-supervised sampler timeouts, and durable Bayesian-fit fallback states. It does not add public attribution APIs, TrustEnvelope output, frontend confidence logic, production attribution semantics, LLM authority, or deterministic-truth mutation.

## Implemented Artifacts

- `backend/requirements-bayesian.txt` pins the Bayesian dependency lane: `pymc==5.28.5`, `arviz==0.23.4`, and `threadpoolctl==3.6.0`. PyTensor is intentionally resolver-owned by PyMC and resolved in Docker as `pytensor==2.38.3`.
- `backend/Dockerfile.bayesian` defines the isolated Bayesian worker image with OpenBLAS/build dependencies, single worker concurrency, one PyMC core/chain, BLAS thread caps, and worker-scoped `PYTENSOR_FLAGS`.
- `backend/app/bayesian/runtime_policy.py` validates native thread budget and timeout hierarchy before scientific imports.
- `backend/app/bayesian/runtime_probe.py` provides import smoke, PyTensor compile, thread budget, compiledir concurrency, tiny PyMC benchmark, and supervisor-kill probes.
- `backend/app/bayesian/sampler_supervisor.py` kills sampler children by process group and includes a synthetic blocking child for kill-path proof.
- `backend/app/bayesian/runtime_state.py` persists timeout and stale-running fallback states only to `public.bayesian_model_fits`, with transaction-local `app.current_tenant_id` binding.
- `alembic/versions/007_skeldir_foundation/202605281200_b24_p5_runtime_statuses.py`, `backend/app/bayesian/enums.py`, `backend/app/bayesian/models.py`, and `db/schema/canonical_schema.sql` add `timeout` and `worker_lost` fit statuses.
- `.github/workflows/b2_4-gate-dry-run.yml`, `Makefile`, `docs/ci/enforcer_registry.yaml`, and `docs/ci/gate_subsumption_matrix.yaml` wire the P5 gate.
- `scripts/ci/validate_b24_p5_runtime_harness.py` enforces the P5 boundary and negative controls.
- `backend/tests/test_b24_p5_runtime_harness.py` covers runtime policy, process supervision, tenant-scoped runtime state, and delayed scientific imports.

## Negative Controls

The P5 validator intentionally fails closed for:

- missing OpenBLAS/native thread cap
- missing process-group creation
- missing real PyMC benchmark call
- missing durable timeout write
- missing tenant GUC binding

## Boundary Proof

- No P5 public route or router registration was added.
- No frontend Bayesian confidence threshold logic was added.
- No LLM/provider import was added to the Bayesian runtime path.
- Timeout and stale-running repair write only to `public.bayesian_model_fits`.
- Scientific imports are delayed until after runtime thread and compiledir policy is applied.

## Non-Overclaim

This pack proves local P5 implementation and local harness behavior. It does not prove protected-main CI, production deployment, full B2.4 business attribution semantics, TrustEnvelope delivery, or protected-branch merge state. The current local branch is `codex/b24-p4-feature-authority` and was behind `origin/main` during verification, with unrelated pre-existing evidence-document moves and graph outputs in the working tree.
