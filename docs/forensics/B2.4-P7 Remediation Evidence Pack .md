# B2.4-P7 Remediation Evidence Pack

## Scope

This report covers B2.4-P7 only: diagnostic semantics, governed ArviZ reduction, interval availability conditionality, bounded child result summaries, durable diagnostic persistence, and CI/governance wiring for the P7 proof lane.

This report does not claim full B2.4 completion. B2.4-P8 artifact lifecycle, B2.4-P9 tenant hygiene, B2.4-P10 projection, TrustEnvelope confidence delivery, and production Bayesian attribution rollout remain outside this completion boundary.

## Initial Findings

H01 was validated at the start of this remediation: the first P7 implementation was not complete by the directive's own Definition of Complete. The missing proof was not cosmetic. It lacked falsifiable Postgres constraint execution, unskipped ArviZ execution, protected-branch adjudication, and protected-main landing evidence.

The architectural failure mode was a semantic leak between "sampled" and "trustworthy interval." A Bayesian child process could produce samples while the parent and persistence layer still lacked an enforceable physical rule that credible intervals are unavailable unless all governed diagnostics pass. In system-physics terms, the posterior trace, diagnostic reducer, parent state machine, and database row were under-coupled: energy could enter the system as a sampled result without passing through a hard diagnostic gate before interval exposure.

The second empirical finding came from the local real-fit proof. The P5/P6 child process environment was too sparse for Windows native/PyTensor import physics: absent home/config and loader variables caused child-process import failures before sampling. The remediation keeps the environment allowlisted, but adds explicit non-PII PyTensor config/home anchors and Windows loader variables so the scientific runtime can initialize without inheriting profile or secret-bearing parent state.

## Implemented Closure

- Added a centralized P7 diagnostic policy with versioned diagnostic, target-filter, and interval-policy identifiers.
- Reduced ArviZ diagnostics inside the sampler child only; parent execution paths remain free of PyMC/PyTensor/ArviZ imports.
- Replaced ungoverned or skipped interval semantics with explicit pass/fail/error/unavailable diagnostic states and enumerated failure reasons.
- Made credible interval availability conditional on all governed predicates: finite diagnostics, R-hat <= 1.01, ESS >= 400, divergences == 0, bounded HDI shape/size, and no fallback.
- Added bounded result-summary validation rejecting trace-like payloads, non-finite numbers, NetCDF/Zarr-style artifacts, and oversized summaries.
- Added PostgreSQL columns and constraints on `bayesian_model_fits` for diagnostic status, failure reason, HDI bounds, policy versions, interval payload bounds, and `diagnostics_computed_at`.
- Added a P7 GitHub Actions proof job with Postgres service, Bayesian dependencies, required DB proofs, and the P7 static validator.
- Updated required-status governance, topology, enforcer registry, and gate-subsumption metadata for the P7 proof lane.
- Hardened the P5/P6 child environment discovered during empirical P7 validation: Windows child processes now receive only explicit loader variables plus synthetic non-PII PyTensor home/config controls.

## Architectural Remediation

P7 now treats diagnostics as a first-class contract, not as explanatory metadata. The sampler child owns native statistical reduction because it is already the bounded native-runtime lane. It emits only a byte-capped, schema-validated summary; full traces and artifact-like payloads are rejected before durable write.

The parent fit executor now has a deterministic interpretation layer for diagnostic-stage failures. A child that dies after sampling but during diagnostics or interval adjudication no longer collapses into a generic worker failure; it becomes a diagnostic failure mode with interval unavailable.

Postgres now enforces the final physical invariant: `credible_interval_status = 'available'` is impossible unless diagnostic status is `passed`, no fallback is applied, R-hat/ESS/divergence thresholds are satisfied, HDI bounds exist, and policy-version fields are present. This prevents API, worker, or future refactor drift from presenting unvalidated intervals.
