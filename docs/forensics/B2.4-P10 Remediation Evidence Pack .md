## Executive Verdict

**IN PROGRESS - LOCAL FALSIFIABLE VALIDATION COMPLETE; PROTECTED MAIN VALIDATION PENDING**

B2.4-P10 implements an internal, read-only confidence projection over the accepted B2.4 P1-P9 substrate. The implementation intentionally does not compute attribution, schedule Bayesian work, expose a public FastAPI route, alter frontend decision UX, or introduce LLM authority. It projects deterministic revenue as the left-hand truth, optionally attaches Bayesian fit metadata when a matching source snapshot exists, and always emits backend-owned confidence metadata with explicit unavailable reasons.

This evidence pack will be updated after protected PR merge and final green `main` CI validation. Until then, no authoritative-main completion claim is made here.

## Contextual Interpretation

The contextual framing documents and current repository state converged on the following constraints:

1. P1-P9 are the accepted B2.4 substrate for authority schema, deterministic source windows, sparse privacy, fit planning, resource bounds, convergence diagnostics, artifact lifecycle, and worker tenant hygiene.
2. P10 is a projection boundary, not a compute boundary. It must read already-materialized deterministic revenue and already-persisted Bayesian fit/artifact metadata.
3. Deterministic attribution remains sovereign. Missing, stale, failed, nonconverged, or unavailable Bayesian evidence must not suppress or mutate deterministic revenue.
4. Confidence semantics are backend-owned and versioned. The frontend may display backend output later, but it must not own threshold logic or infer confidence locally.
5. P10 must be falsifiable in CI through static negative controls and behavioral tests, not through prose-only evidence.

## Remediation Artifacts

### Backend Projection

- `backend/app/bayesian/api_projection.py`
  - Builds the read-only SQL projection.
  - Uses deterministic revenue as the left relation.
  - Joins fit metadata only by tenant, model type/version, source window, and exact `source_snapshot_hash`.
  - Emits source-snapshot mismatch as an explicit confidence reason rather than attaching stale fit data.
  - Reads artifact lifecycle metadata without artifact payload bytes.

### Confidence Semantics

- `backend/app/bayesian/confidence_policy.py`
  - Defines `CONFIDENCE_POLICY_VERSION = "b24-p10-confidence-policy-v1"`.
  - Emits buckets: `high`, `medium`, `low`, `unavailable`.
  - Emits reasons including `no_fit`, `nonconverged`, `bad_rhat`, `low_ess`, `divergence`, `timeout`, `worker_failure`, `input_too_large`, `artifact_unavailable`, `source_snapshot_changed`, and interval-width reasons.

- `backend/app/bayesian/confidence_metadata.py`
  - Defines strict Pydantic DTOs for deterministic, Bayesian, credible interval, confidence, and audit metadata.
  - Keeps the projection internal and payload-free.

### Tests and Validators

- `backend/tests/test_b24_p10_projection.py`
  - Verifies SQL shape, deterministic-left behavior, no-fit preservation, bucket classification, unavailable reason mapping, DTO validation, authority-field absence, and static negative controls.

- `scripts/ci/validate_b24_p10_projection.py`
  - Enforces required files, SQL shape, forbidden imports, no public API exposure, no frontend thresholding, workflow wiring, required-status wiring, and multiple negative controls.
