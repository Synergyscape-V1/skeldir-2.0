## Directive Scope

This follow-up closes the B2.5-P7 audit durability and chronological determinism gaps without implementing later Trust API phases. It remains limited to provenance/audit persistence and explicitly excludes signing, verification, JWKS, routes, machine-caller auth, rate limiting, export, MCP adapters, LLM generation, and action authority.

## Initial Findings

The previously merged P7 baseline at `58b35ecea14f86e22b7fe794bae605775b40951d` was insufficient for the follow-up directive because:

- Audit rows were written through the caller-provided session, so a caller rollback after audit construction could erase the audit record.
- The primary validation path used fake sessions and static checks; it did not prove rollback survival on PostgreSQL.
- `TrustAuditRequest.created_at` was optional, and `_audit_material` / `_params` fell back to `datetime.now(timezone.utc)`, allowing live clock values into audit hash material.
- The P7 workflow defined PostgreSQL URLs but did not provision a PostgreSQL service or force a DB-backed proof.

## Remediation Implemented

- Made `TrustAuditRequest.created_at` required and timezone-aware.
- Removed live-clock fallback from audit hash material and DB timestamp parameters.
- Added `record_trust_audit_event_durable`, which opens a dedicated audit session, sets `app.current_tenant_id`, and commits audit persistence independently of the caller transaction.
- Rewired `build_unsigned_trust_envelope_with_audit` to use durable audit persistence for issuance and refusal rows.
- Added a PostgreSQL-only durability test that:
  - proves same-session audit writes disappear after caller rollback,
  - proves durable audit writes survive caller rollback,
  - proves idempotent retry keeps `audit_ref` / `audit_hash` stable,
  - verifies one access row, one issuance row, one replay row, and replay count `1`.
- Hardened `scripts/ci/validate_b25_p7_provenance_audit.py` with follow-up markers for PostgreSQL transaction proof, rollback coupling, serialization-return failure survival, clock-source containment, delayed retry hash stability, missing/default created_at rejection, and SQLite primary-proof rejection.
- Updated `.github/workflows/b2_5-p7-provenance-audit.yml` to provision PostgreSQL, apply migrations through the existing migration-authority action, force `SKELDIR_B25_P7_POSTGRES_PROOF=1`, and run the PostgreSQL proof in CI.
