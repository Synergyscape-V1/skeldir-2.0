dictionary can no longer reach the TrustEnvelope private key. Signing requires an
immutable, content-addressed `AuthorizedTrustEnvelope` capability that can be minted
only after a successful production P5 build, durable P7 audit composition, exact
reconstruction of P7's bounded transform, complete claim correspondence, and the
producing-policy check preserved from Corrective XIII.

classification does not convert source inspection into runtime proof and does not
claim that public JWKS verification independently proves producing authority. Public
verification proves the authenticity and integrity of the issued bytes; the new
pre-sign capability boundary makes false-authority bytes ineligible for issuance.

## 2. Starting falsifier and root cause

On the exact starting lineage, the XIII provenance guard correctly refused a forged
runtime-policy tuple. It did not protect the rest of the signed semantic surface.
Three independent Audit 54 contradictions were reproduced:

```text
false deterministic money          -> signed -> public JWKS verification accepted
foreign tenant/subject identity     -> signed -> public JWKS verification accepted
available -> degraded + provenance removed
                                      -> signed -> public JWKS verification accepted
```

The builder and audit stages flattened authoritative observations into ordinary
mutable dictionaries. The final signer accepted any dictionary that satisfied wire,
canonicalization, and the narrower Bayesian provenance rules. Call history was the
only evidence that a payload had passed the builder, tenant/source adapters, and
durable audit. Consequently:

- builder correctness was mistaken for issuance correctness;
- schema validity, canonical validity, and authority validity were conflated;
- `confidence_status` could select a weaker validation branch and erase the evidence
  that made an originally available claim true;
- financial, identity, and source-window correspondence were not modeled at the
  private-key boundary; and
- a signature proved only possession of bytes, not that Skeldir's own authorities
  had licensed those bytes for issuance.

The root cause was architectural, not three missing `if` statements: **ordinary
mutable payloads erased proof-of-authority state before the consequence-bearing
private-key operation**.

## 4. Chosen issuance physics

```text
authenticated request + tenant-scoped authoritative rows
  -> P5 TrustEnvelope builder
  -> immutable TrustEnvelopeBuildWitness
       [P5 canonical bytes, tenant, subject, snapshot, 41-field authority set]
  -> P7 durable audit composition
  -> reconstruct exactly(P5 payload + declared P7 transform)
  -> compare canonical semantics AND exact shape-preserving structure
  -> validate identity + finance + source/window + confidence + policy
  -> mint module-sealed AuthorizedTrustEnvelope
  -> P8 capability-only signer validates its content address
  -> select active TrustEnvelope key
  -> domain-separated Ed25519 signature
  -> public JWKS verification
```

`encode_envelope_structure_snapshot()` is the single internal shape-preserving
serializer. It is explicitly not signature material; signature and semantic hashes
continue to use the governed canonicalization authority. This distinction prevents a
JSON convenience encoder from becoming a second canonicalization protocol.

P7 may replace only `audit_ref`, `audit_hash`, the audit provenance entries,
`semantic_truth_hash`, and `signature_hash`. P8 may replace only signing metadata,
derived hashes, and `signature`. Every other mutation is a refusal.
