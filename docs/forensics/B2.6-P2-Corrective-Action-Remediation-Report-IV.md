## 6. Live findings fixed in-cycle (with log evidence)

**FINDING 1 — beat broker-session wedge (H-IV-B07, live).** After a broker
permission fault, beat kept firing the sweep every 5s but every apply
failed with `PendingRollbackError` on the same poisoned kombu session
(kombu caches one session per channel; rolls back only on
OperationalError). Beat alive, schedule intact, supervision green, zero
recovery forever. Fixed by `HealingBeatScheduler` (drops cached
producer/connection on apply failure; next tick rebuilds). Proven: outage
-> natural recovery with 0 restarts across repeated runs.

**FINDING 2 — pooled-producer wedge bricks the API (live).** Failed
publishes return poisoned producers to kombu's pool
(`close_resource` is a no-op); after ~pool-size faults the engine pool
dries (`QueuePool limit of size 5 overflow 0 ... timed out`) and the API
serves nothing broker-touching while alive. Fixed by
`reset_broker_pools_after_fault` on all four production publish fault
paths (API immediate/redrive/followup, relay).

**FINDING 2b — naive `pools.reset()` is suicide (proven deterministically,
then fixed).** kombu marks reset pools closed and `acquire` on the stale
object raises `Acquire on closed pool`; celery's app holds its producer
pool by direct reference (`app.amqp._producer_pool`), so a bare reset
converts the first transient fault into a PERMANENT publish outage for
the process (CI recovery hid past its wait on 6 ratcheted failures:
attempts=6, next_retry pushed +90s past the 240s window). The helper
therefore ALSO drops the app-held reference (celery's own `_after_fork`
precedent), forcing lazy recreation of a fresh pool on next publish.
Proven by a send→reset→send regression test (fails before, passes
after) and the full deployed recovery journey.

**FINDING 3 — migration DML under FORCE RLS silently no-ops (live).**
`migration_owner` (non-superuser, no bypassrls) sees 0 rows without a
tenant GUC, so the legacy NULL-window backfill matched zero rows
silently (and the ingress JOIN side stayed hidden even after disabling
dispatch alone). Fixed with transient DISABLE on both tables + UTC-explicit
`date_trunc` + ENABLE+FORCE restore. Proven by the upgrade-path probe
(202609072001-era NULL row -> 2026-01-15 UTC day + strict trigger guard).
Note: Corrective-III's backfill had the same property (harmless there via
column DEFAULTs).
