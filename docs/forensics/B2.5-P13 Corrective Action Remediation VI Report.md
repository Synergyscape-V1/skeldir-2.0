## Initial falsification findings

The Directive VI and both independent audits were treated as one system-physics problem. The central defect was not an isolated authorization typo: the system had collapsed API read authority, Bayesian worker authority, scheduler reachability, persisted lifecycle truth, wire-version truth, and proof-oracle truth into surfaces that could each make the others appear healthy.

1. `app_user` inherited effective register/claim and Bayesian write authority. A tenant-facing process could mint worker-process authority, rewrite dispatch state, and call the governed claim function. The C5 terminal trigger limited the last mutation but did not remove the escalation path.
2. `plan_due_dirty_events()` had no production caller. Dirty events were durable but causally inert: no bounded scheduler/worker path transformed committed source changes into fit intents and outbox work.
3. The planner left expired dirty leases stranded and had no durable, revision-aware wake-up protocol for overlap, crash, or restart.
4. The production fit-claim statement omitted schema-required dispatch fields and allowed `REUSED` to share the dispatch lane. A same-snapshot terminal fit could therefore touch or revive terminal outbox bookkeeping.
5. Terminal immutability did not cover every confidence-projection dependency. In particular, identity/window columns remained outside the frozen authority set.
6. Lifecycle vocabularies were duplicated across SQL and runtime code, and the outbox terminal vocabulary did not consistently include `dead_lettered`.
7. The evidence-skew literal was duplicated rather than owned by one policy artifact.
8. C5 had added wire fields to the v1 envelope without a schema-version transition. Historical-v1 validation and active issuance were therefore semantically conflated.
9. The downgrade matrix did not distinguish unknown version, relabeled v1 carrying v2 fields, and malformed v2 missing required v2 fields with exact failure classes.
10. G5 expected dispositions were produced through the same classifier under test, making the oracle circular.
11. G8 inferred read-only behavior from row-count observations rather than capturing the SQL emitted by the real Trust route.
12. The prominent proof counter could be assembled independently of the completed journey and persisted artifact, allowing decorative or partial success accounting.

## Remediation design and implementation

### 1. Physical worker authority boundary

The provisioning boundary now creates `app_worker` as a distinct login. It receives the existing read roles but no reverse membership exists from `app_user`, `app_ro`, or `app_rw` into `app_worker`. Migration `202608201200` never creates cluster roles: it installs worker grants only when deployment provisioning has created `app_worker`, leaves those capabilities unreachable in legacy migration-only topologies, and rejects any shared/application role that can inherit the worker when it is present.

The migration revokes worker-process registration, generation, claim, running, completion, failure, recovery, and planner functions from `PUBLIC`, `app_user`, `app_ro`, and `app_rw`, then grants them only to `app_worker`. Direct mutation of fits, artifacts, dispatch outbox, and execution leases is revoked from the API/shared roles. The worker receives only the Bayesian tables and Postgres Celery broker/result tables its production path actually exercises. `app_user` remains the authenticated HTTP principal.

The Bayesian boot probe now verifies `current_user = 'app_worker'`; topology or connectivity alone is insufficient. The physical proof evaluates both `has_function_privilege`/`has_table_privilege` and an actual denied register call as `app_user`, then proves the corresponding worker calls and writes remain available.

The first protected-CI iterations falsified an unsafe migration assumption: legacy jobs intentionally migrate as an identity without `CREATEROLE`, and the initial compatibility floor tried to create `app_worker` inside Alembic. The correction cleanly separates cluster provisioning from schema migration. A fresh isolated PostgreSQL cluster with only `app_user`, `app_rw`, and `app_ro` now completes the entire historical chain through `202608201200`; `app_worker` remains absent and worker execution privileges remain false. A second fresh database prepared through the deployment provisioner creates the worker and passes both physical authority/orchestration tests. The migration also defers its final trigger-function and wake-up-table revocations until after trigger construction and backfill so a least-privilege migration owner can build the objects without weakening their final ACLs.

Protected CI then exposed two packaging/wiring omissions: the P13 physical job had not supplied the repository's required direct-Postgres topology attestation, and the canonical local backend image did not contain the new temporal-policy artifact loaded at import time. The P13 job now supplies the same explicit topology, attestation, provenance, and connection-lifetime affinity fields used by the B2.4 worker gates. The backend image now copies `contracts/trust-api`, and the C6 closure validator makes both requirements non-optional.

The first fully attested P13 run then falsified an isolation assumption in the physics test itself: the preceding composition suite intentionally leaves an older pending dirty-event wakeup, and the global scheduler correctly served that older tenant before the newly created proof tenant. The proof now drives the real bounded one-tenant scheduler repeatedly until its uniquely identified stimulus is delivered, requires that delivery to be exactly one `CLAIMED` dispatch, then requires the next replay to report zero work and verifies exactly one target fit/outbox row. It therefore tests production ordering instead of assuming an empty global ledger.

### 2. Durable production planner reachability

A non-payload wake-up ledger, `b24_fit_planner_wakeups`, is maintained transactionally by the production dirty-event trigger. Its rows contain tenant, monotonically increasing revision, status, and bounded lease metadata—never source payloads.

`b24_due_fit_planner_tenants()` is worker-only, bounded to 100, and uses `FOR UPDATE SKIP LOCKED`. Expired leases are eligible again. `b24_complete_fit_planner_wakeup()` deletes only the revision actually completed; if a newer source change arrives during processing, the row is released back to pending instead of losing the wake-up.

The registered Celery task `app.tasks.bayesian.plan_due_fit_intents` is default-wired into Beat every 60 seconds. It leases a bounded tenant batch, invokes the production planner, records dispatchable versus reused results, and acknowledges or releases each revision in `finally`. The runtime proof creates real B2.3 financial state through `app_user`, calls the production dirty marker, sends the real worker-init signal, invokes the registered task, observes exactly one queued fit and one pending outbox row, then invokes the task again and observes zero duplicate work.

### 3. Claim, REUSED, dead-letter, and terminal truth semantics

The claim CTE now supplies all schema-required dispatch columns. `claimed_for_dispatch` is true only for `CLAIMED`; `REUSED` is a separate terminal-observation lane and always returns `dispatch_outbox_id = null`. Dispatch upsert logic preserves terminal outbox states, including `dead_lettered`, and excludes terminal fits from dispatch creation or activation.

The live P13 claim matrix terminalizes a failed fit, explicitly marks its associated outbox row `dead_lettered`, re-observes the identical source snapshot through `claim_fit_for_snapshot()`, and proves the result is `reused`, the dispatch identifier remains null, the fit stays failed, and the outbox remains dead-lettered.

The terminal-fit trigger now freezes the complete 28-column projection dependency registry, including model identity, version, and source window. The same registry is cross-checked against the read model and database trigger so a newly consumed field cannot silently remain mutable.

### 4. Governed lifecycle and temporal policy

`contracts/bayesian/lifecycle-taxonomy.v1.yaml` owns fit/outbox statuses, terminal sets, and reuse policy. `contracts/trust-api/temporal-policy.v1.yaml` owns the 120-second skew and freshness ceiling. Runtime confidence policy loads that artifact; the C6 validator compares the registries with SQL and runtime branches.

### 5. Honest wire evolution and downgrade failure classes

Historical `trust-envelope.v1.yaml` and `evidence-temporal-boundary.schema.json` were restored to their pre-C5 shape. Active issuance now uses immutable `trust-envelope.v2.yaml` and `evidence-temporal-boundary.v2.schema.json`; OpenAPI, export v2, builder defaults, canonicalization, schema registries, active examples, and hash-domain declarations point to v2. A frozen `historical_v1_pre_c5.json` fixture proves v1 remains verifiable without pretending it carries v2 temporal semantics.

Verification now distinguishes:

- unknown schema version: registry error;
- v1 relabeled with v2-only fields: `schema_downgrade_rejected`;
- v2 missing its required fields: `schema_version_contract_mismatch`.

The downgrade matrix contains eight executable cases and checks the exact reason class. Canonical and semantic hashes were regenerated for the active v2 fixtures.

### 6. Independent oracles and non-vacuous completion

G5 uses a literal disposition oracle defined independently of the production prompt-control classifier. C6 negative control NC-C6-09 mutates the production mapping and proves the independent expectation fails.

G8 instruments the real Trust route's global SQLAlchemy engine. It captures emitted statements, identifies the fit read, requires exact tenant and fit predicates, and rejects writes and live aggregate recomputation (`SUM`, `AVG`, `MIN`, `MAX`, `COUNT`). NC-C6-10 injects a forbidden aggregate and proves the oracle fires.

`p13_c6_completed_proof_journeys` is the only success counter. It is appended only after every expected case has executed, no case is missing, the evidence manifest is serialized, written, read back, and hash-verified. Other counters are explicitly observations, not completion claims.
