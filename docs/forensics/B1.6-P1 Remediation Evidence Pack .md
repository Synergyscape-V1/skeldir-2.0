# B1.6-P1 Remediation Evidence Pack

Date: 2026-03-30  
Phase: B1.6-P1 (Authority Contract Lock + DB Failure-Sink Prerequisite)  
Mode: Production remediation with falsifiable static/runtime/CI proofs

## 1) Initial Findings (Pre-Remediation)

From B1.6 inventory and direct `main` code/runtime inspection:

- Investigation and budget result payloads had no explicit field-level authority classes; deterministic and synthesis content coexisted without a typed authority contract.
- No typed upstream `validation_context` existed to carry deterministic truth into later B1.6 validation phases.
- `provider_boundary.py` was central and generic, but lacked a dedicated B1.6-P1 drift guard against future domain SQL/import creep.
- `llm_validation_failures` existed in schema with RLS, but runtime app identity could not write; local runtime probes produced `InsufficientPrivilegeError`.
- Breaker behavior was implemented for provider failures, but B1.6 policy (semantic validation failures must remain request-local and non-breaker-opening) was not explicitly codified as a machine-checkable contract.
- Worker paths persisted raw provider text (`provider_summary`) into authority-facing payloads and fallback builders consumed it directly.

## 2) Root-Cause Validation

Confirmed root causes on `main`:

- B0.7 provider boundary optimized transport/budget/cache/breaker correctness but did not encode B1.6 authority semantics.
- B1.5 lifecycle introduced deterministic-vs-synthesis separation in API shape but did not lock field authority classes in worker-owned contracts.
- Failure sink table provisioning and RLS were complete, but runtime-role grants for `llm_validation_failures` were missing in authoritative migration grant surfaces.
- Existing retries/breaker taxonomy were provider/transport-oriented; semantic validation failure accounting policy was not explicitly locked.

## 3) Remediations Implemented

### 3.1 Authority contract lock + typed validation context (upstream)

- Added worker/service-owned typed contract module:
  - `backend/app/llm/authority_contract.py`
- Added contract builders owned outside provider boundary:
  - `backend/app/services/llm_authority_contract.py`
- Contract explicitly classifies fields as:
  - `deterministic_authority`
  - `validated_synthesis`
  - `audit_only_raw_provider_artifact`
- Added typed generic `ValidationContext` with deterministic truth payload and source metadata for downstream B1.6-P2/P3 use.

### 3.2 Worker write-path authority enforcement

- Updated `backend/app/workers/llm.py`:
  - investigation/budget success paths now build and persist typed authority payloads (including `validation_context`) through service-owned lifecycle writes.
  - contract-build failures are fail-closed and recorded into validation-failure sink, then authority jobs are failed with `validation_failed`.
- Preserved provider boundary generic role; no investigation/budget SQL injected there.

### 3.3 Failure-sink operational prerequisite

- Added ORM model:
  - `backend/app/models/llm.py` (`LLMValidationFailure`)
  - exported via `backend/app/models/__init__.py`
- Added structured sink service:
  - `backend/app/services/llm_validation_failures.py`
- Added authoritative runtime grant migration:
  - `alembic/versions/007_skeldir_foundation/202603301230_b16_p1_validation_failure_sink_grants.py`
  - grants `SELECT, INSERT` to `app_rw`/`app_user`, `SELECT` to `app_ro`.

### 3.4 Generic boundary preservation guardrail

- Added CI scanner preventing domain imports/symbols/domain-table SQL identifiers in provider boundary:
  - `scripts/ci/enforce_b16_p1_provider_boundary_domain_sql.py`
- Added non-vacuous negative-control fixture + tests:
  - `backend/tests/fixtures/forbidden_provider_boundary_domain_sql_fixture.txt`
  - `backend/tests/test_b16_p1_provider_boundary_domain_sql_enforcer.py`

### 3.5 Breaker accounting policy lock

- Updated `backend/app/llm/provider_boundary.py`:
  - added `_is_breaker_eligible_failure` and `_apply_breaker_failure_accounting`.
  - policy: only `provider_timeout` and `provider_error:*` are breaker-eligible.
  - semantic validation failures are request-local and non-breaker-opening.
- Added tests:
  - `backend/tests/test_b16_p1_breaker_accounting_policy.py`

### 3.6 API compatibility for contract-shaped payloads

- Updated coercion paths to parse new authority payloads first and keep backward-compatible fallbacks:
  - `backend/app/api/investigations.py`
  - `backend/app/api/budget.py`

### 3.7 CI wiring

- Updated `.github/workflows/ci.yml` to run:
  - B1.6-P1 boundary-domain guard + enforcer tests
  - B1.6-P1 authority/sink/breaker proof suite
