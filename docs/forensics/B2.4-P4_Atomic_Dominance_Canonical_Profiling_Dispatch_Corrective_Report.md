## 4. Prior Failure: ON CONFLICT Was Not Dominance

Prior behavior prevented duplicate active execution rows but allowed faster-commit-wins semantics. That is insufficient for Hash A / Hash B ordering because an older frozen retry could pass a Python supersession check before a newer candidate became dominant.

## 5. Prior Failure: Hash-Scoped Profiling Fanout

`b24_p4_profiling_leases` was keyed by tenant/model/window/hash, so Hash A, Hash B, and Hash C could each acquire separate profiling rows for one tenant/window. That reduced duplicate same-hash work but did not bound window-level planner resource use.

## 6. New DB-Boundary Dominance Design

`claim_fit_for_snapshot` now seeds the canonical lane if absent, then locks `b24_active_execution_leases` by tenant/model/version/window with `FOR UPDATE`. Under that lock it evaluates `newer_dominant_snapshot` across active owner, fit, and dispatch outbox evidence before fit claim/outbox visibility. Stale Hash A returns `source_snapshot_superseded` with no dispatchable outbox.

## 7. SERIALIZABLE Is Not Primary

No SERIALIZABLE transaction-isolation strategy was added. The proof is physical: row lock plus conditional dominance check at the claim boundary.

## 8. Atomic Supersession and Claim/Outbox Proof

The claim path contains:

- `locked_execution_lane AS`
- `FOR UPDATE`
- `newer_dominant_snapshot AS`
- `claimable_execution_lane AS`
- `claimed_fit AS`
- `dispatchable_outbox AS`
- `activated_execution_lane AS`

The runtime smoke proof against disposable Postgres returned a `FitClaimResult(... outcome=CLAIMED ..., active_execution_status='dispatch_pending')` and a pending outbox id.

## 10. Newer Hash B Wins Even If Older Hash A Reaches INSERT First

The lane seed remains idempotent and non-authoritative. Dominance is checked after locking the lane and before dispatchable outbox visibility; stale Hash A becomes `source_snapshot_superseded`.

## 11. Canonical Window-Level Profiling Ownership

`acquire_profiling_lease` now uses `public.b24_active_execution_leases` keyed by tenant/model/version/window. `source_snapshot_hash` is metadata, not part of the active ownership key. This blocks multi-hash profiler fanout.

## 13. Anti-Split-Brain Ownership Proof

Active profiling no longer inserts or updates `b24_p4_profiling_leases`. The separate table remains schema history/audit surface, but canonical ownership is the P3 active-execution lane.

## 14. Profiling Before Authority and Envelope Math

Planner ordering remains:

`acquire_preflight_lease` -> `acquire_profiling_lease` -> feature authority validation -> P4 envelope math -> claim/outbox.

Tests assert profiling ownership is acquired before `load_source_window_feature_authority` and before `evaluate_source_snapshot_resource_bounds`.

## 15. Transactional Authority-Build Dispatch

`request_feature_authority_build` uses `WITH upserted_request AS (...), queued_dispatch AS (...)` to create the request and build outbox in one transaction. `dispatch_due_feature_authority_builds` actively leases due rows with `FOR UPDATE SKIP LOCKED` and publishes `FEATURE_AUTHORITY_BUILD_TASK`.

## 16. Active Dispatcher / Sweeper Recovery-Only

Normal path is active outbox dispatch. The bounded sweeper remains a retry/timeout recovery hook, not the primary authority-build trigger. Validator rejects passive-polling-only replacement.

## 17. Output Non-Regression / P5 Gate

P4 still has no artifact, TrustEnvelope, current-output, sampler, or projection publication path. `B24_P5_OUTPUT_NON_REGRESSION_ENTRY_GATE` now explicitly blocks B2.4-P5 artifact/current-output writes until they call `assert_snapshot_artifact_not_regressing_current_output`.

## 18. Frozen Retry Preservation

Frozen authority retry still validates feature authority for Hash A before any latest P2 recompute. Hash A and Hash B dirty lifecycles remain `source_snapshot_hash` scoped.

## 19. P4 Envelope Preservation

Non-superseded retries still run the existing feature-width and graph-complexity checks before claim/outbox. Over-cap authority counts continue to yield `feature_width_exceeded` or graph-specific fallback.

## 20. P3 Compatibility

After P4 pass, the candidate enters the normal P3 active execution / fit claim / dispatch outbox path. Queue payload remains fit-id-only. Dispatch remains absent until fresh authority and P4 pass.
