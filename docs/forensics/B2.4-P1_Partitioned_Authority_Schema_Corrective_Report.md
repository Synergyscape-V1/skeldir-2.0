## 3. Final Table-Family Decisions

`bayesian_model_fits` is now a PostgreSQL partitioned parent table using `PARTITION BY HASH (tenant_id)` with 16 initial partitions. The partition key matches the RLS predicate, tenant-scoped query paths, tenant-bound artifact linkage, and all parent-level PK/UNIQUE constraints.

`bayesian_artifacts` is also now partitioned by `HASH (tenant_id)` with 16 initial partitions. This avoids carrying a non-partitioned envelope exception for artifact lifecycle volume.

## 4. Constraint Strategy

- Primary key strategy: `PRIMARY KEY (tenant_id, id)` on both partitioned parents.
- Unique strategy: fit identity remains `UNIQUE (tenant_id, model_type, model_version, source_window_start, source_window_end, source_snapshot_hash)`.
- Tenant-bound FK: `bayesian_artifacts(tenant_id, fit_id) -> bayesian_model_fits(tenant_id, id) ON DELETE RESTRICT`.
- Null safety: `tenant_id`, `model_type`, `model_version`, `source_window_start`, `source_window_end`, and `source_snapshot_hash` remain `NOT NULL`.
- Storage: `bayesian_model_fits` child partitions are created with `fillfactor=90`.
