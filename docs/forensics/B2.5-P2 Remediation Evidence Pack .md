## Root-Cause Findings

The original P2 proof established deterministic canonicalization, hash-domain manifests, serializer boundaries, and schema/canonicalization registries, but its Unicode evidence was anchored to display-only text. That left a semantic proof gap: non-ASCII UTF-8 bytes could be canonicalized without proving they participated in semantic hash identity.

The original implementation also relied on disciplined construction of hash input wrappers rather than validating wrapper closure as a first-class invariant. That made wrapper-key and payload-domain attacks testable only indirectly.

The CI validator already invoked `backend/tests/trust`, but successful pytest output was hidden by `capture_output=True`; authoritative CI logs could therefore prove the validator passed, but not visually prove the executed pytest command or passed count.

Strengthened `backend/app/trust/hash_identity.py` with a closed `validate_hash_domain_wrapper()` gate before canonical byte encoding. Allowed wrapper keys are exactly `hash_domain`, `schema_version`, `canonicalization_version`, `hash_algorithm`, and `payload`.

Added/updated tests in `backend/tests/trust` for semantic Unicode raw UTF-8 bytes, semantic-hash participation, wrapper rejection, and manifest coverage count.

Corrected the original `revenue_claim_valid.expected.json` UTF-8 prefix. The hash and byte length were already correct; the dormant prefix field had not previously been checked.
