## 3. Sovereign-root relational model

**Sovereign facts** (owned by predecessor contract, immutable once
authoritative): ingress identity, tenant binding, event clock
(`event_timestamp`), provider, verified state (`authenticity_verified`).

**Derived facts** (recomputed from sovereign, never stored as authority):
canonical UTC-day window (`b26_p2_canonical_day_start/end`, IMMUTABLE
SQL, parity vs Python 13/13); admission verdict (resolver); P2 scope
(Python derivation over sovereign inputs); operational disposition
(function of dispatch/outbox/quarantine/telemetry agreement).

**Projections** (must equal derived or be re-verified before
consequence): outbox twin, directory entry, broker message claims,
conduction receipt (tuple/window/count bound server-side; scope witness
shaped), conducted state.

**Enforcement:**
- `trg_b26_p2_dispatch_sovereign_window` (BEFORE INSERT/UPDATE of
  window/ingress/tenant/provider): stored window must equal
  `canonical_day(event_clock)`, provider must equal ingress provider,
  ingress must be visible + verified. Fail-closed on missing ingress.
- `trg_b26_p2_ingress_sovereign_custody` (BEFORE UPDATE OF
  clock/tenant/provider OR DELETE): refuses once any dispatch
  references the ingress (no drift, no orphan, no silent cascade).
- `b26_p2_resolve_dispatch_authority` (SECURITY DEFINER, same
  signature): directory → tenant bootstrap → dispatch+ingress
  re-established → stored-vs-canonical verified → RETURNS THE CANONICAL
