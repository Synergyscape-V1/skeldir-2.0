### Re-executed by Agent-2 against the *remediated* inherited tree

This is the finding that reopened the corrective. Against Agent-1's completed
architecture, on a live PostgreSQL 15 database at Alembic head, as the ordinary
`app_user` runtime role (`rolsuper=false`, `rolbypassrls=false`):

```
--- E1: failed -> issued, fabricated well-shaped 64-byte evidence, ONE statement ---
 issuance_state | issued_signing_key_id  | sig_len
 issued         | kid:forged-by-app-user |      64
UPDATE 1
```

Four further ordinary-principal mutations were accepted on the same substrate:
`signature_outcome_unknown → issued` with fabricated evidence; `issued → failed`
(durable history denying a real prior issuance); substitution of the signature
bytes and key id on an already-`issued` row; and, with the unrelated NOT NULL
columns supplied, insertion of a fabricated `issued` row.

**Classification: FAIL.** This is Audit 58 Finding 2, sub-case 1, unclosed —
and simultaneously the governing directive's §10 matrix rows *"issued +
fabricated but well-shaped evidence"*, *"forbidden predecessor → issued"*,
*"issued → state denying prior issuance"*, and *"direct transition bypassing
intended authority mechanism"*, and its §20 automatic-`NOT COMPLETE` condition
*"ordinary runtime DB authority can manufacture completed issuance"*.

### Novel findings established by Agent-2

**Finding XVI-1 — shape can never carry consequence.** `octet_length = 64` is
not a stronger claim than a 64-hex-character regex. Any principal able to write
the row can write 64 fabricated bytes. No CHECK constraint, and no self-
consistency binding between the hash and the bytes, can distinguish a real
Ed25519 signature from a fabricated one, because PostgreSQL 15 cannot verify
Ed25519 and the caller supplies both operands. The only physical closure is
that the principal permitted to assert completed issuance is **not** the
ordinary application principal.

**Finding XVI-2 — API/export issuance-truth divergence.** For one physical
consequence — *signature exists, payload judged unsafe to externalise* — the
read path recorded `issued` (safety asserted after the durable completion write)
while the export path recorded `signature_outcome_unknown` (safety asserted
inside the signing `try`). Beyond violating XVI-C's equality, the export
behaviour *understated known truth*: the signature was in memory at the moment
the row was marked unknown.

**Finding XVI-3 — retry erased prior signing consequence.** The attempt
transition set `issuance_outcome_unknown_at = NULL` and retained nothing.
A request that produced a signature, lost its outcome, then retried
successfully, ended as an ordinary `issued` row indistinguishable from a
first-attempt success — even though two valid signatures may physically exist
for that one logical request. This is XVI-D's *"history must model that
reality"* and §20's *"retry creates contradictory or unreconstructable
lineage."*

## N. What is not claimed

1. **Independence.** Every runtime result in this report was executed by the
   implementing agent. Nothing here is independent acceptance, and no
   engineering result converts XVI-I into a self-certified `PASS-RUNTIME`.
2. **Database-verified signature authenticity.** The database enforces *who*
   may assert completed issuance, the *shape* of the evidence, and the *legal
   history* of the assertion. It does not and cannot verify that the retained 64
   bytes are a valid Ed25519 signature over the envelope.
3. **`signature_outcome_unknown` understates one known case.** When the signer
   returns and only the durable completion write is refused, the process *knows*
   a signature exists, but the strongest fact it can durably record — given that
   the completion transition was just refused — is that a signing consequence
   occurred and its completion is unresolved. The state is honest about the
   uncertainty of the *record*, not about the process's in-memory knowledge, and
   the retained lineage counter preserves the fact for later reconstruction.
4. **Crash convergence was injected, not induced.** Failures were injected at
   the governed boundaries and the reconciler was driven with an explicit
   `stale_before`. No OS process was physically killed mid-signature.
5. **Deployment concurrency is closed by configuration.** Two concurrent
   production deployments were not induced against a real production database.
6. **The migration downgrade is lossy.** Stated in §I rather than presented as a
   lossless round trip.
7. **PostgreSQL 16 parity is not claimed** for any P13 property.
8. **The E2E composition proof result in §L was produced on a clock-compensated
   local substrate** to work around Docker VM clock drift. It is a regression
   check. The authoritative execution is CI, recorded in §J.
9. **No hosted CI claim is made anywhere in this report until §J is completed
   from GitHub-supplied facts.**
