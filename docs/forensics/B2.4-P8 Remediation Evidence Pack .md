# B2.4-P8 Remediation Evidence Pack

## Phase

`B2.4-P8 - Artifact Persistence, Lifecycle, and Storage Governance`

## Initial Findings

P8 began with a real blocker, not a documentation gap:

- `backend/app/bayesian/artifact_repository.py` was P1-era read-only and explicitly stated artifact generation, pruning, and storage lifecycle were out of scope.
- `bayesian_model_fits.artifact_ref` and `artifact_hash` could be populated by `fit_execution.py` without a corresponding governed artifact row.
- The current artifact taxonomy still allowed `posterior_trace`, `object_storage`, `local_fs`, and `zstd`, which conflicts with the corrected P8 directive.
- `bayesian_artifacts` had metadata fields but no stored payload bytes, exact stored-byte hash verification path, lifecycle status, tombstone metadata, tenant quota row, or bounded pruning operation.
- P7 correctly blocked ungoverned full trace persistence, but P8 had not yet supplied the only allowed governed artifact path.

## Remediation Summary

Implemented P8 as a Postgres-native small-artifact governance phase:

- Added `backend/app/bayesian/artifacts.py` with versioned P8 policy, JSON canonicalization, exact byte hashing, hard byte/JSON caps, PII-key rejection, internal ref validation, and bounded gzip decompression via `decompressobj`.
- Replaced the read-only artifact repository with governed persistence, verification, idempotent replay, per-fit WAL budget checks, tenant quota accounting, and bounded pruning with tombstone metadata.
- Added Alembic migration `202606061200_b24_p8_artifact_lifecycle.py` for `payload_bytes`, `payload_json`, `payload_byte_count`, lifecycle fields, `pruned_metadata`, and `bayesian_artifact_storage_quotas` with RLS.
- Tightened current enums and ORM constraints: no `posterior_trace`, no object/local storage backend, no `zstd`, active payloads capped at 64 KiB, and active internal URI refs constrained to `b24://artifact/...`.
- Updated `fit_execution.py` so sampled result summaries persist through `persist_artifact_sync()` before linking `bayesian_model_fits.artifact_ref/hash`.
- Added P8 static and DB proof tests plus `scripts/ci/validate_b24_p8_artifact_lifecycle.py` with negative controls.
- Wired `B2.4-P8 Artifact Lifecycle Proof` into the B2.4 workflow, Makefile target, required-status contract, enforcer registry, subsumption matrix, and CI topology map.

## Follow-Up Corrective Action - 2026-06-07

The follow-up directive found two material residual risks in the initial P8 implementation:

- Payload airgap risk: `payload_bytes` lived on the primary ORM entity and `BayesianArtifactRepository.get_by_ref()` returned that entity, so metadata/lifecycle/quota callers could accidentally hydrate stored bytes.
- Concurrent quota risk: the tenant quota byte reservation used an atomic conditional update for bytes, but the normal persistence path still had `SELECT ... FOR UPDATE` reads and no deterministic multi-connection proof that artifact count/bytes could not exceed quota under contention.

Corrective remediations implemented on `codex/b24-p8-follow-up-corrective`:

- Added payload-free `ArtifactMetadata`, explicit `ArtifactPayload`, `artifact_metadata_select()`, `get_metadata_by_ref()`, and `get_payload_by_ref()` accessors in `backend/app/bayesian/artifact_repository.py`.
- Changed `BayesianArtifact.payload_bytes` to SQLAlchemy `deferred=True, deferred_raiseload=True`; accidental ORM access now raises instead of lazy-loading payload bytes.
- Removed normal persistence-path `FOR UPDATE` reads. The only remaining repository `FOR UPDATE` is bounded pruning maintenance with `FOR UPDATE SKIP LOCKED`.
- Added tenant artifact count governance: `MAX_P8_TENANT_ARTIFACT_COUNT`, `max_tenant_artifact_count`, `bayesian_artifact_storage_quotas.max_artifact_count`, and `active_artifact_count <= max_artifact_count`.
- Replaced tenant quota charging with one atomic conditional `UPDATE ... RETURNING active_bytes, active_artifact_count` covering both bytes and count.
- Added first-class `rejected` artifact lifecycle rows. Tenant quota rejection now persists a small reason-coded metadata row with `payload_bytes IS NULL`, `payload_byte_count = 0`, and `pruned_metadata.rejection_reason = tenant_quota_exceeded`; active bytes/count are not incremented.
- Updated fit execution so storage quota rejection marks the fit as failed/fallback with `storage_quota_exceeded` rather than linking a missing or rejected payload as a successful artifact.
- Added Alembic migration `202606071200_b24_p8_follow_up_airgap_quota.py` and synchronized `db/schema/canonical_schema.sql`.
- Strengthened `scripts/ci/validate_b24_p8_artifact_lifecycle.py` with required checks and negative controls for raiseload, metadata projection, atomic count guard, rejected metadata, and forbidden normal `FOR UPDATE`.
- Added deterministic live PostgreSQL proof `test_b24_p8_atomic_quota_allows_exactly_two_concurrent_artifacts`: six independent backend connections synchronize on a barrier with quota allowing two artifacts; the expected terminal state is exactly two active artifacts, four rejected zero-payload metadata rows, no active quota overrun, and no worker failure.
