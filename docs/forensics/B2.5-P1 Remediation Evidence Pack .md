### Corrective Hypothesis Adjudication

H-CA-01 - Flattened TrustEnvelope required semantics were too broad.
Status: CONFIRMED. The prior schema globally required revenue, match, attribution, and discrepancy fields, forcing non-revenue subjects to carry semantically false fields.
Remediation: `contracts/trust-api/trust-envelope.v1.yaml` now keeps only common authority fields globally required and uses subject-conditioned `if`/`then` rules for `revenue_claim`, `match_verdict`, `attribution_result`, `reconciliation_discrepancy`, and `confidence_projection`.

H-CA-02 - Non-revenue and degraded examples fabricated money.
Status: CONFIRMED. Confidence/degraded/refusal-style envelopes carried `verified_revenue_minor`/`currency` despite not being revenue claims.
Remediation: Non-revenue examples no longer include fabricated money. Dedicated positive controls prove confidence projection, degraded confidence, and refusal envelopes validate without revenue fields.

H-CA-03 - The validator lacked dual positive/negative conditionality proof.
Status: CONFIRMED.
Remediation: `scripts/ci/validate_b25_p1_contracts.py` now validates subject-conditioned required and forbidden fields with positive fixtures and typed negative controls.

H-CA-04 and H-CA-07 - Runtime-model drift was not protected by the B2.5-P1 contract workflow.
Status: CONFIRMED. Existing schema drift coverage was DB-oriented and the B2.5-P1 workflow did not watch backend trust/envelope model paths.
Remediation: Added `scripts/ci/validate_b25_p1_trust_drift.py`, a `make validate-b25-p1-trust-drift` target, and B2.5-P1 workflow path filters/steps for backend trust/envelope drift.

H-CA-05 - Validity windows were unbounded.
Status: CONFIRMED.
Remediation: Trust validation now rejects `valid_until <= created_at` and `valid_until > created_at + 86400s`.

H-CA-06 - Evidence temporal boundaries were incomplete.
Status: CONFIRMED.
Remediation: `contracts/trust-api/evidence-temporal-boundary.schema.json` now requires `evidence_snapshot_hash`, `max_source_read_skew_ms`, and `snapshot_consistency_status` in addition to snapshot/read/freshness fields.

H-CA-08 - Recursive closure was incomplete.
Status: PARTIALLY CONFIRMED. Core TrustEnvelope schemas were mostly closed, but the OpenAPI JWKS key object allowed undeclared sibling keys.
Remediation: Closed the JWKS key item object and added recursive object-closure validation for contract schemas.

H-CA-09 - Type-confusion controls were too narrow.
Status: CONFIRMED.
Remediation: Negative controls now mutate authoritative fields into arrays, objects, booleans, and malformed values across subject, evidence, signing, and authority surfaces.

H-CA-10 - Signing allowlist needed renewed positive and negative proof.
Status: RE-VERIFIED.
Remediation: Positive controls prove allowed signing algorithms validate; negative controls reject forbidden algorithms and wrong types.

H-CA-11 - Protected-main completion must be proven after merge.
Status: PASS.
