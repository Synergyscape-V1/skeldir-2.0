# B2.5-P7 Remediation Evidence Pack

## Directive Scope

B2.5-P7 is limited to Context Robust Hypothesis Anchored provenance and audit persistence for TrustEnvelope issuance/refusal behavior. It does not authorize signing, verification endpoints, JWKS, machine-caller auth, scope enforcement, rate limiting, export, MCP adapters, public routes, or action authority.

## Initial Findings

The inherited B2.5 state had P1-P6 coverage for contract authority, canonicalization, text disposition, money authority, unsigned builder assembly, and reason truth semantics. The remaining P7 gap was physical provenance/audit persistence:

- No canonical source-class registry covered webhook ingress identity, provider-native references, B2.3 verdict lineage, B2.4 confidence/artifact placeholders, policy/text/money/reason decisions, and audit identity.
- The P5 builder emitted placeholder audit fields and only shallow provenance.
- No tenant-scoped audit tables existed for access, issuance, replay, or scope denial.
- No RLS/FORCE-RLS policy or idempotent uniqueness constraint protected those audit rows.
- No merge-blocking validator proved provenance ordering, audit hash stability, wrong-tenant refusal, scope-denial evidence suppression, or P1-P6 preservation.

- Added canonical provenance assembly in `backend/app/trust/provenance.py`.
