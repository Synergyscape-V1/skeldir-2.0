# B2.5-P7 Remediation Evidence Pack

## Directive Scope

B2.5-P7 is limited to Context Robust Hypothesis Anchored provenance and audit persistence for TrustEnvelope issuance/refusal behavior. It does not authorize signing, verification endpoints, JWKS, machine-caller auth, scope enforcement, rate limiting, export, MCP adapters, public routes, or action authority.

## Initial Findings

The inherited B2.5 state had P1-P6 coverage for contract authority, canonicalization, text disposition, money authority, unsigned builder assembly, and reason truth semantics. The remaining P7 gap was physical provenance/audit persistence:

- No canonical source-class registry covered webhook ingress identity, provider-native references, B2.3 verdict lineage, B2.4 confidence/artifact placeholders, policy/text/money/reason decisions, and audit identity.
- The P5 builder emitted placeholder audit fields and only shallow provenance.
- No tenant-scoped audit tables existed for access, issuance, replay, or scope denial.
- No RLS/FORCE-RLS policy or idempotent uniqueness constraint protected those audit rows.
- No merge-blocking validator proved provenance ordering, audit hash stability, wrong-tenant refusal, scope-denial evidence suppression, or P1-P6 preservation.

## Remediation Implemented

- Added canonical provenance assembly in `backend/app/trust/provenance.py`.
- Added deterministic audit hash/ref identity in `backend/app/trust/audit_hash.py`.
- Added idempotent trust audit persistence and audit attachment wrapper in `backend/app/trust/audit.py`.
- Added Alembic migration `202607011200_b25_p7_trust_audit_provenance.py` for:
  - `trust_access_log`
  - `trust_envelope_issuance_log`
  - `trust_replay_events`
  - `trust_scope_denial_events`
  - tenant FK, hash constraints, idempotency uniqueness, RLS, FORCE RLS, tenant GUC policy, and scoped grants.
- Extended the provenance-chain contract enum surface for P7 authority values only.
- Added `backend/tests/trust/test_b25_p7_provenance_audit.py`.
- Added `scripts/ci/validate_b25_p7_provenance_audit.py` with non-vacuous positive and meta-negative controls.
- Added `.github/workflows/b2_5-p7-provenance-audit.yml`.
- Registered the gate in `Makefile`, `docs/ci/enforcer_registry.yaml`, `docs/ci/gate_subsumption_matrix.yaml`, and this forensics index.
- Updated `db/schema/canonical_schema.sql` and `db/schema/canonical_schema.yaml` for the P7 audit tables.

## PR-CI Follow-Up Remediation

The first protected PR run for #600 proved the dedicated P7 workflow but exposed integration gate drift:

- `B2.5-P7 Provenance Audit`: pass.
- `Validate Migrations`: failed because the intentional downgrade `DROP TABLE` rollback annotation was not on the scanned line.
- `validate-schema-authority`: failed because canonical schema authority did not yet include the P7 audit tables.
- `m0-maintainability-scope-lock` and `m1-local-dev-authority`: failed because their phase allowlists had not registered the P7 workflow, validator, migration, and evidence pack.

Follow-up remediation:

- Moved the migration rollback `CI:DESTRUCTIVE_OK` annotation onto the literal `DROP TABLE` statement.
- Added P7 validator/workflow/migration/evidence paths to the M0 and M1 allowed surfaces.
- Patched canonical SQL with the migration-derived P7 table, constraint, index, FK, policy, and RLS entries.
- Added matching P7 audit table metadata to `db/schema/canonical_schema.yaml`.
