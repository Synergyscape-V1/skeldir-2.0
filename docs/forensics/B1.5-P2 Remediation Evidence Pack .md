## 1) Initial Findings (Pre-Remediation)

From `docs/forensics/B1.5_Context_Inventory_Report.md`, `api-contracts/openapi/v1/llm-investigations.yaml`, and `api-contracts/openapi/v1/llm-budget.yaml`:

- Public status vocabularies were compute-centric and omitted review authority states (`ready_for_review`, `approved`, `rejected`, `refine_requested`, `rerun_requested`).
- Review mutations were absent from both public contracts.
- Budget launch `status_url` pointed to `/api/budget/recommendations/{job_id}/status` while that route did not exist.
- No idempotency contract semantics existed for review mutations.
- Result schemas mixed deterministic decision objects and LLM narrative text without explicit authority separation.
- CI semantic contract checks did not include B1.5-P2-specific assertions for the above invariants.

## 3) Remediations Implemented

### 3.1 Investigation contract addendum

Updated: `api-contracts/openapi/v1/llm-investigations.yaml`

- Added domain-specific retrieval route: `GET /api/investigations/{investigation_id}`.
- Added explicit review mutation routes:
  - `POST /api/investigations/{investigation_id}/approve`
  - `POST /api/investigations/{investigation_id}/reject`
  - `POST /api/investigations/{investigation_id}/refine`
  - `POST /api/investigations/{investigation_id}/rerun`
  - `POST /api/investigations/{investigation_id}/retry`
  - `POST /api/investigations/{investigation_id}/cancel`
- Added canonical lifecycle status enum in contract:
  - `submitted`, `validating`, `investigating`, `ready_for_review`, `approved`, `rejected`, `refine_requested`, `rerun_requested`, `completed`, `failed`, `timeout`, `cancelled`.
- Added truthful launch links:
  - `status_url` -> `/api/investigations/{investigation_id}/status`
  - `result_url` -> `/api/investigations/{investigation_id}`
- Added structured authority separation:
  - `deterministic_findings` (authoritative)
  - `llm_synthesis` (explicitly non-authoritative)

### 3.3 Idempotency contract semantics (all review mutations)

For every review mutation route across both domains:

- Required request header: `X-Idempotency-Key` (via `./_common/parameters.yaml#/components/parameters/idempotency_key`).
- Duplicate-response contract text in operation descriptions (explicit replay semantics).
- Response header: `X-Idempotency-Replayed`.
- Response body required fields:
  - `idempotency_key`
  - `idempotency_replayed`
  - `mutation_accepted`
