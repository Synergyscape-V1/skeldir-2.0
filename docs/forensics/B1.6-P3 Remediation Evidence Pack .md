# B1.6-P3 Corrective-Action Remediation Evidence Pack

Date: 2026-03-31 (America/Chicago)

## 1) Corrective Baseline Findings (Re-validated on `main`)

- Numeric authority checks were present but permissive: unresolved binding/truth extraction could silently skip and still pass.
- Numeric validation was centralized but still expressed as a loose loop with weakly-typed binding semantics, reducing composability.
- Cache replay had mismatch fallback, but no durable anti-runaway mechanism to suppress repeated provider spend after repeated numeric rejection.
- P3 tests did not explicitly cover missing-truth failure, missing-claim failure, per-binding tolerance override, repeated numeric-rejection cache economics, or direct router coercion negatives.

## 2) Corrective Remediations Implemented

### 2.1 Canonical kernel composition + fail-closed binding enforcement

Updated `backend/app/llm/output_validation.py`:

- Added typed policy/evaluation primitives:
  - `NumericAuthorityBindingSpec`
  - `NumericAuthorityPolicySpec`
  - `NumericAuthorityValidationResult`
- Moved numeric policy construction into `_numeric_authority_policy(...)` with explicit configuration-error capture.
- Enforced fail-closed semantics for unresolved authority comparisons:
  - missing/invalid deterministic truth mapping,
  - invalid binding config,
  - missing truth path,
  - missing/unextractable claim path,
  - non-numeric resolved values.
- Kept numeric failures machine-typed as `numeric_mismatch` so worker deterministic fallback behavior remains intact.
- Kept one canonical tolerance authority path:
  - default tolerance from `numeric_tolerance_ratio` (default 5%),
  - per-binding override from `NumericClaimBinding.tolerance_ratio`.

### 2.2 Cache replay anti-runaway and truth-aware cache semantics

Updated `backend/app/llm/provider_boundary.py`:

- Added validation-context fingerprinting to cache key derivation:
  - fingerprint now tracks bound truth snapshot + numeric bindings + tolerance metadata.
  - avoids stale cache reuse under meaningful deterministic-truth drift while ignoring unrelated truth fields.
- Added numeric-rejection cache marker state:
  - marker TTL suppresses repeated provider calls for repeated numeric-authority rejection on same cache identity.
  - replay path can short-circuit from marker and return `validation_numeric_mismatch` without new provider spend.
- Added marker upsert path when provider attempts exhaust on numeric mismatch.
- Preserved breaker policy separation:
  - numeric authority failures remain semantic validation failures, not breaker-accountable provider failures.

### 2.3 Expanded falsifiable P3 proofs

Updated `backend/tests/test_b16_p3_numeric_authority.py` with new adversarial and boundary tests:

- missing truth path fails closed in kernel (`numeric_mismatch`)
- missing claim extraction fails closed in kernel (`numeric_mismatch`)
- binding-driven tolerance override proof:
  - default 5% pass case
  - per-binding 1% override fail case
- cache anti-runaway proof:
  - repeated numeric rejection does not repeatedly call provider
  - subsequent request uses cache marker path and incurs zero provider cost
- direct router/API coercion negative controls:
  - rejected synthesis is suppressed by investigation coercion helper
  - rejected synthesis is suppressed by budget coercion helper
