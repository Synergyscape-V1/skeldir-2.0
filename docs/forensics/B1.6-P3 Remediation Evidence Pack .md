## 2) Remediation Changes

### 2.1 Schema-composed numeric authority path

Updated `backend/app/llm/output_validation.py`:

- Added Pydantic V2 schema-associated numeric enforcement via `_StrictOutputModel` `@model_validator(mode="after")`.
- The validator consumes worker-supplied context through `ValidationInfo.context` and evaluates numeric authority from within schema validation.
- Numeric failures now raise `PydanticCustomError("numeric_mismatch", ...)` carrying structured mismatch metadata.
- `validate_provider_output_text(...)` now passes context into `schema_model.model_validate(..., context=...)` and maps schema-emitted numeric failures to typed `OutputValidationResult(code="numeric_mismatch")`.
- Structural/schema and semantic numeric failures now flow through one schema-composed validation path while retaining existing typed output contract.

### 2.2 Zero fresh provider call on ordinary drift for existing cache identity

Updated `backend/app/llm/provider_boundary.py`:

- Removed `validation_context_fingerprint` participation from `_cache_key(...)` so existing cache identity is reused for drift adjudication instead of forcing a miss and fresh generation.
- On cache-hit numeric mismatch:
  - records `cache_numeric_mismatch` validation failure row,
  - writes/upserts numeric rejection marker,
  - releases reservation,
  - finalizes as `validation_numeric_mismatch`,
  - returns failed cached result,
  - and exits before provider call.
- This enforces zero fresh LLM calls on first ordinary drift detection for existing identity.
- Breaker semantics unchanged: numeric failures remain semantic validation failures.
