# B1.6-P3 Remediation Evidence Pack

Date: 2026-03-31  
Phase: B1.6-P3 (Numeric Authority Enforcement via Worker-Supplied Validation Context)  
Mode: Production remediation with falsifiable local runtime + CI-gate proof wiring

## 1) Initial Findings (Validated on `main`)

- Provider-boundary validation still stopped at structural/schema checks; there was no canonical numeric authority comparison against worker-supplied truth.
- `ValidationContext` existed but was semantically under-populated for numeric enforcement (`numeric_claim_paths` only, no typed claim binding/tolerance metadata).
- Cache-hit and replay validation paths did not include numeric authority checks.
- Worker success sinks assumed synthesis success on schema validity; there was no typed numeric-mismatch handling that preserved deterministic readiness.
- API coercion could still surface non-validated synthesis content.
- CI had P1/P2 checks, but no dedicated P3 hallucinated-numeric adjudication gate.

## 2) Remediations Implemented

### 2.1 Worker-supplied numeric authority contract

Updated authority contract and builders:

- `backend/app/llm/authority_contract.py`
  - contract version advanced to `b1.6-p3` (backward-parse compatible with `b1.6-p1`)
  - added typed `NumericClaimBinding` (`claim_path`, `truth_path`, optional `tolerance_ratio`)
  - `ValidationContext` now carries:
    - `numeric_claim_bindings`
    - canonical `numeric_tolerance_ratio` (default `0.05`)
- `backend/app/services/llm_authority_contract.py`
  - `build_validation_context(...)` now accepts typed bindings + tolerance
  - authority payload builders accept worker-supplied `validation_context`
  - synthesis state is now explicit (`validated` on pass, `rejected` on numeric mismatch)

Workers now populate context with deterministic truth and numeric claim bindings from worker-owned prompt context:

- `backend/app/workers/llm.py`
  - added numeric context assembly helper (`_build_numeric_validation_context`)
  - merged deterministic truth + numeric claim bindings + tolerance into `ValidationContext`

### 2.2 Canonical numeric authority policy in the boundary kernel

Updated `backend/app/llm/output_validation.py`:

- introduced canonical policy constants:
  - `NUMERIC_AUTHORITY_DEFAULT_TOLERANCE_RATIO = 0.05`
  - `NUMERIC_AUTHORITY_POLICY_ID = "b1.6-p3-numeric-authority-v1"`
- added numeric authority check after schema parse and before success emit:
  - compares extracted numeric claims against deterministic truth via worker-supplied bindings
  - applies one shared tolerance policy (default 5%, with optional per-claim override)
  - emits typed validation outcome `numeric_mismatch` with machine-readable details

### 2.3 Boundary/cache/replay enforcement wiring

Updated `backend/app/llm/provider_boundary.py`:

- all validation stages now consume `validation_context`:
  - provider path
  - cache-hit re-validation path
  - idempotent replay path
- numeric mismatch is promoted to typed failure reason:
  - `validation_numeric_mismatch`
- numeric authority failures remain semantic validation failures (breaker-ineligible)
- cache replay mismatch path now records `cache_numeric_mismatch` and bypasses cache to fresh path.

### 2.4 Deterministic supremacy on synthesis rejection

Updated `backend/app/workers/llm.py`:

- when boundary returns `validation_numeric_mismatch`, workers:
  - persist deterministic authority payloads
  - persist synthesis artifact with `validation_state="rejected"`
  - preserve audit-only raw provider artifact
  - keep authority job flow at `ready_for_review` (deterministic path remains available)

### 2.5 API fallback/coercion fail-closed for non-validated synthesis

Updated:

- `backend/app/api/investigations.py`
- `backend/app/api/budget.py`

Both coercion paths now only surface `llm_synthesis` when `validation_state == "validated"`.  
Rejected/unvalidated synthesis is not surfaced on response success paths.

### 2.6 CI adjudication wiring for P3

Updated `.github/workflows/ci.yml`:

- added `Run B1.6-P3 numeric authority enforcement gate`
- gate command:
  - `pytest -q backend/tests/test_b16_p3_numeric_authority.py`
