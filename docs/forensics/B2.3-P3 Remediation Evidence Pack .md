## Initial Finding

The P3 phase-contract stop condition was valid.

The inherited P1 schema constraint `ck_b23_match_verdicts_discrepancy_amount_consistency` physically bound `discrepancy_amount_minor` to `canonical_net_verified_amount_minor`. That made ordinary full refunds indistinguishable from severe attribution discrepancies at the database authority boundary. The result was a mathematical contradiction with P3: normal net revenue adjustments would necessarily generate false attribution alerts.

The authorized phase-exception migration corrects that substrate defect by binding discrepancy authority to gross expected revenue versus gross captured checkout revenue.

## Remediations Performed

1. Added targeted Alembic migration `202605051200_b23_p3_verdict_persistence_authority.py`.
2. Replaced the flawed net-based discrepancy consistency constraint with a gross-basis constraint:
   - `abs(canonical_expected_gross_amount_minor - canonical_captured_gross_amount_minor)`.
3. Recomputed discrepancy amount, ratio, and band from gross expected/captured authority during migration.
4. Added `b23_revenue_events.is_gross_capture_correction` to distinguish normal net adjustments from original gross capture corrections.
5. Updated canonical schema authority for the corrected discrepancy basis and gross-correction event flag.
6. Patched `match_engine_kernel.py` so P2/P3 discrepancy calculations are permanently decoupled from `canonical_net_verified_amount_minor`.
7. Added normal post-capture adjustment handling for partial refunds, full refunds, chargebacks, reversals, and provider adjustments.
8. Added gross capture correction handling that recomputes gross captured amount, discrepancy amount, discrepancy ratio, discrepancy band, and exception lifecycle.
9. Added deterministic attribution exception lifecycle reconciliation for:
   - clean to flagged,
   - clean to alert,
   - flagged to alert,
   - alert to flagged,
   - flagged to clean,
   - alert to clean.
10. Added a database partial unique index so only one open or acknowledged exception can exist per tenant/verdict.
11. Added Postgres-native transition sweepers for:
   - `pending` to `unmatched`,
   - `matched_provisional` to `matched_confirmed`.
12. Registered both transition sweepers through Celery task registration and beat cadence.
13. Declared P3 transition cadence at five minutes, with `FOR UPDATE SKIP LOCKED` next-run liveness.
14. Added strict Pydantic response models for P3 match verdict and exception reads with `extra="forbid"`.
15. Added minimal row-level read endpoints:
   - `GET /api/reconciliation/match-verdicts/{verdict_id}`,
   - `GET /api/reconciliation/exceptions`,
   - `GET /api/reconciliation/exceptions/{exception_id}`.
16. Updated OpenAPI and generated frontend TypeScript types for the P3 read surfaces.
17. Added recursive backend/OpenAPI parity enforcer for P3 response models.
18. Added P3 governance contract and non-vacuous negative controls.
19. Added CI wiring for P3 static enforcement, backend parity, frontend type drift, and runtime Postgres proof-lock.

## Runtime Proof-Lock

The P3 runtime proof module is intentionally not a pass-by-skip proof in CI. `.github/workflows/ci.yml` sets `SKELDIR_B23_P3_REQUIRE_DB_PROOFS=1`, verifies the migrated Postgres substrate exists, and fails if runtime proofs are skipped.

Required CI runtime coverage includes:

- pending records older than `WEBHOOK_ARRIVAL_WINDOW` transition to `unmatched`;
- pending records inside the window remain `pending`;
- rows skipped by `FOR UPDATE SKIP LOCKED` transition on the next cadence sweep after lock release;
- tenant-scoped sweeps do not mutate another tenant's eligible rows;
- provisional records older than `PROVISIONAL_MATCH_WINDOW` transition to `matched_confirmed`;
- provisional records inside the window remain `matched_provisional`;
- normal refunds update net verified revenue without creating attribution exceptions;
- gross capture corrections drive discrepancy recomputation and exception lifecycle.
