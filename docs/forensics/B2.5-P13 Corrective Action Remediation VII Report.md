## 1. What this corrective was actually about

Corrective Action VII did not ask for more tests. It asked whether Skeldir can
prove **conservation of epistemic work and authority** from every B2.4-relevant
financial-state transition through durable scheduling, legitimate worker
production, immutable confidence authority, and the final signed TrustEnvelope.

The governing law is that every authority-bearing state transition must either
propagate into the next required authority state, or terminate in an explicit,
machine-visible, governed refusal. It must never vanish silently.

Three things vanished silently on `6030560e0`:

1. A financial truth change could commit with **no dirty signal at all**.
2. A dirty signal could exist and be **destroyed by a planner that did nothing**.
3. Security hardening could be **undone by a routine lifecycle operation**.

Everything below is organised around making those three physically impossible,
and then proving it with evidence that fails when the property fails.

## 4. Exit Gate C7-D / C7-E — Source-change invalidation completeness and atomicity

### 4.1 Design

The canonical question the directive poses is decidable:

> Would this committed state transition change the bytes produced by the
> authoritative B2.4 source snapshot?

Each source relation contributes rows only when it satisfies a membership
predicate, and contributes bytes only through a fixed projection. So a committed
mutation changes snapshot bytes exactly when it moves a row into or out of the
member set, or changes a projected column of a member row.

`backend/app/bayesian/source_invalidation_contract.py` renders that decision
procedure as PostgreSQL statement-level triggers, derived from
`ALLOWED_SOURCE_READ_MODELS` and the authoritative source-query filters.

### 4.2 Source-change / invalidation authority map

| Source relation | Window key | Membership predicate (from the authoritative query) | Projected columns | Invalidation mechanism | Atomic? |
| --- | --- | --- | --- | --- | --- |
| `attribution_events` | `occurred_at` | `processing_status IN ('processed') AND event_type IN ('conversion')` | 11 | `trg_b24_invalidate_attribution_events_{insert,update,delete}` | yes |
| `attribution_allocations` | `created_at` | `verified = true` | 12 | `trg_b24_invalidate_attribution_allocations_{insert,update,delete}` | yes |
| `b23_match_verdicts` | `last_transition_at` | `status IN ('matched_confirmed', 'adjusted')` | 19 | `trg_b24_invalidate_b23_match_verdicts_{insert,update,delete}` | yes |
| `b23_revenue_events` | `event_occurred_at` | `event_type IN ('payment_capture', 'partial_refund', 'full_refund', 'chargeback_lost', 'chargeback_won', 'reversal')` | 14 | `trg_b24_invalidate_b23_revenue_events_{insert,update,delete}` | yes |

12 triggers, 4 relations, insert/update/delete each. Coverage is derived from the
contract, not enumerated by hand: `GOVERNED_INVALIDATION_EXCEPTIONS` is empty and
the gate fails if any relation in `ALLOWED_SOURCE_READ_MODELS` is not governed.

Statement-level triggers with transition tables were chosen over row-level so a
500-row batch transition produces one dirty event per affected `(tenant, day)`
bucket rather than 500.

### 4.3 Behavioural evidence

`test_c7_source_change_creates_durable_obligation` runs the exact production
statement and observes the full chain:

```text
in-snapshot rows: 0 -> 1  (snapshot bytes CHANGED: True)
dirty_events: 1 -> 2
newest dirty event: ('b23_match_verdicts_snapshot_changed', 'b23_match_verdicts', 'pending')
planner wakeup rows: 1
```

`test_c7_invalidation_is_transactionally_coupled` performs crash injection:

```text
inside txn: source mutated, dirty_events 2 -> 3 (same transaction)
after rollback: dirty_events=2 source_match_quality=high
```

Neither the committed source truth nor the obligation survives independently.
Because the trigger fires inside the writer's transaction, there is no window in
which one exists without the other.

`test_c7_non_snapshot_transition_does_not_invalidate` proves **precision**, which
the directive explicitly required (§16, "do not mechanically dirty on every
verdict status change"):

```text
pending -> unmatched applied: rows=1
in-snapshot rows: 0 -> 0 (snapshot bytes changed: False)
dirty_events: 1 -> 1
```

`pending -> unmatched` is excluded from the B2.4 source set on both sides, so it
cannot change snapshot bytes and correctly produces no planner work.

### 4.4 Successor safety

The directive's falsifier (§33) is that a new production writer changing a
contract field without calling the invalidation mechanism must turn CI red.
Under this design the falsifier is stronger than red CI: **there is no code path
between the write and the trigger.** A new writer cannot bypass invalidation
because invalidation is not something writers do.

Two gates guard the mechanism itself:

- `NC-C7-S03` mutates the generated DDL in the migration; the gate re-renders
  from the contract and refuses the drift.
- `NC-C7-S04` removes `b23_match_verdicts` from the invalidation contract; the
  gate refuses because coverage no longer equals the source contract.
- `NC-C7-B02` (CI, behavioural) drops the live trigger and proves the causality
  proof goes red with `produced no invalidation`, then green again on restore.

**C7-D: PASS. C7-E: PASS.**

## 5. Exit Gates C7-F / C7-G / C7-H — Planner-obligation conservation

### 5.1 The state model

A wake-up was modelled as a transient notification. It is now a durable
obligation to revisit the tenant until no dirty state requires a later planner
opportunity.

`b24_complete_fit_planner_wakeup` reads residual authority atomically at
completion — the same debounce arithmetic the production planner applies,
evaluated against the tenant's remaining unplanned state — and returns a
machine-visible disposition instead of a boolean:

| State | Disposition | Wake-up outcome | Next runnable |
| --- | --- | --- | --- |
| No work exists | `deleted` | row removed | on next signal |
| Eligible work remains after a bounded batch | `retained_eligible` | retained, `next_eligible_at = NULL` | immediately |
| Only future-debounce work remains | `deferred` | retained, `next_eligible_at` set | at computed maturity |
| Transient failure | `released` | lease cleared | immediately |
| Newer revision arrived while running | `stale_revision` | never deleted; lease released | immediately |

Candidates leased by the completing pass are excluded by their live lease, so
"processed" and "not yet processed" are distinguishable. The tenant selector
honours `next_eligible_at`, so a deferred tenant sleeps until due instead of
hot-spinning every beat.

Residual authority is tenant truth under FORCE RLS, so the function requires the
caller to have bound the tenant and raises
`b24_fit_planner_tenant_context_required` otherwise. It can never judge one
tenant's obligation against another's dirty state.

### 5.2 Required scheduler experiments

All against real PostgreSQL with production SQL.

**S1 — pre-debounce (C7-F).** Maturity is real elapsed time against a short real
quiet period; no row is edited to fake it.

```text
T0 wakeup=[('pending', 1, False)] unplanned=1
planner planned 0 (pre-debounce) -> ack disposition = 'deferred'
AFTER ack wakeup=[('pending', 1, True)] unplanned=1
obligation retained (not deleted): True
re-lease suppressed while deferred: True
after quiet period: leased=True planned=1 ack='deleted'
FINAL wakeup=[] unplanned=0
>>> S1 PASS: event planned exactly once, no second stimulus
```

**S2 — bounded backlog (C7-G).** 5 due groups, `candidate_limit=2`.

```text
pass 1: planned=2 disposition='retained_eligible' residual=3 wakeup=[('pending', 1, False)]
pass 2: planned=2 disposition='retained_eligible' residual=1 wakeup=[('pending', 1, False)]
pass 3: planned=1 disposition='deleted'           residual=0 wakeup=[]
>>> S2 PASS: 5/5 drained in 3 ordinary cycles, no new stimulus
```

**S3 — overlap (C7-H).**

```text
planner A leased rev=1 and pauses mid-pass
new dirty evidence arrives -> wakeup=[('pending', 2, False)]
planner B leases the invalidated revision: rev=2 (A held 1)
planner A resumes and acks its stale revision -> 'stale_revision'
wakeup after A's stale ack=[('leased', 2, False)]
>>> S3 PASS: stale ack cannot destroy the newer obligation
```

**S4 — crash / reclaim (C7-I).**

```text
planner A leased revision=1, then dies before ack
live lease cannot be stolen: True
after lease expiry: B reclaimed rev=1 planned=1 ack='deleted'
>>> S4 PASS: crash delayed work, did not lose it
```

**S5 — hot-row preservation.** PR #661's correction is preserved:
`test_c7_bulk_ingestion_does_not_serialize_on_the_wakeup_row` ingests 250 dirty
events and asserts the wake-up row stays at `wakeup_revision == 1`. The
coalescing trigger's update predicate is
`status = 'leased' OR next_eligible_at IS NOT NULL`, which matches nothing in the
steady pending state, so bulk ingestion never touches the row.

### 5.3 Lease duration (C7-J / hypothesis 09)

At baseline the planner wake-up lease was 300s and `BAYESIAN_TASK_TIME_LIMIT_S`
was 300s — exactly equal, no margin. A planner force-killed at its hard limit
could have its tenant reclaimed at the same instant.

The lease is now 600s: the 300s hard limit plus a 300s margin covering warm
shutdown, broker acknowledgement and worst-case database latency. Recovery
latency after a true crash is bounded by that lease plus one beat interval, which
**delays** work without losing it — the directive's stated acceptance. The
relationship is enforced, not asserted: `NC-C7-S09` collapses the lease back to
300s and the gate refuses.

**C7-F: PASS. C7-G: PASS. C7-H: PASS. C7-I: PASS.**

## 6. Exit Gate C7-B — Upgrade-safe least privilege

### 6.1 The correction

The governed runtime privilege set is not a constant. Migrations authored below
revision `202512301930` transfer materialized-view ownership to the runtime
principal, which PostgreSQL permits only while that principal can create in
`public`; at or above that revision, CREATE is exactly the authority the
migration history removed.

Provisioning now reads the **revision graph** — not the live privilege — to
decide. A database whose hardening was undone out of band is recognised as
hardened and re-hardened, rather than mistaken for a virgin cluster that
legitimately needs CREATE. A fail-closed postcondition
(`AuthorityExpansionError`) refuses to report success if the runtime is left
above its governed set.

### 6.2 Three-topology convergence

```text
TOPOLOGY A: fresh cluster -> provision -> migrate to head
  snapshot A -> 68 facts
TOPOLOGY B: historical hardened head -> reprovision -> migrate remaining
  at historical hardened head: app_user CREATE=f
  after reprovision (pre remaining migrations): app_user CREATE=f
  snapshot B -> 68 facts
TOPOLOGY C: cluster at current head -> safe reprovision
  snapshot C -> 68 facts

MACHINE DIFF
AUTHORITY_CONVERGENCE=PASS  (A == B == C across 68 privilege facts)
```

The compared surface is the complete effective permission state for
P13/B2.4-critical objects, not a list of expected privileges: role membership,
schema `USAGE`, schema `CREATE`, table privileges, function `EXECUTE`, ownership,
RLS and FORCE RLS, `BYPASSRLS`, `SET ROLE` reachability, worker authority and
migration authority.

### 6.3 Behavioural falsifier, both directions

`NC-C7-B01` in required CI:

```text
1. GRANT ALL ON SCHEMA public TO app_user   -> app_user CREATE=t
2. required authority proof                 -> RED ("not at the hardened head")
3. real provisioner runs                    -> app_user CREATE=f
4. required authority proof                 -> GREEN
```

Step 2 proves the gate observes real privilege state rather than provisioner
source text. Step 3 proves the correction is active repair, not merely the
absence of a grant.

### 6.4 `migration_owner` membership in `app_worker` — adjudicated

PostgreSQL requires membership in a role to transfer object ownership to it, and
the planner's SECURITY DEFINER functions must be owned by `app_worker`. The
membership is therefore **required**, and is recorded as a governed exception
rather than an oversight.

`NOINHERIT` was implemented and then **withdrawn** after it was found to break
the migration principal: PostgreSQL 15 has no per-membership `INHERIT` option, so
role-wide `NOINHERIT` also strips `migration_owner` of the `pg_database_owner`
authority it needs to migrate at all. That was verified empirically — the chain
failed at `CREATE TABLE alembic_version` — and the change was reverted rather
than worked around.

The exception is bounded by credential custody instead: the migration DSN is
never issued to an API or worker process, which the C7 topology gate asserts
against every in-scope executable topology. The C7 migration additionally
restates the runtime-reachability invariant against both `USAGE` and `MEMBER`,
and `test_c7_worker_functions_reject_non_worker_identity` executes the
directive's named experiment — as `app_user`, `app_rw` and `app_ro`, attempt to
reach `app_worker` by inheritance and by explicit `SET ROLE`, and assert all
paths fail.

### 6.5 Credential-rotation hazard (C7-22) — classified

Repeated provisioning previously issued `ALTER ROLE ... PASSWORD` for existing
roles, so a redeploy could silently rotate a live credential onto a bootstrap
default and collapse the API/worker custody separation the authority boundary now
depends on. Classified as **operational hardening debt with a direct authority
consequence**, and closed minimally: existing roles have their LOGIN capability
ensured but their secret left alone unless `--rotate-existing-credentials` is
passed explicitly. `NC-C7-S12` guards the postcondition; the flag's absence is
asserted by `validate_provisioner_monotonicity`.

**C7-B: PASS.**

## 8. Exit Gates C7-K / C7-L / C7-M — Confidence dependency authority

### 8.1 `created_at` adjudication

The directive required an explicit adjudication rather than a reflexive addition.

Three hypotheses were considered: that `created_at` is the intended immutable fit
lineage timestamp; that a more precise immutable observation time should replace
it; or that freshness ordering should depend on source lineage instead of row
insertion chronology.

**Adjudication: `created_at` is the immutable fit lineage timestamp and is
governed as one.** It is not replaced, because the read model already uses source
lineage where source lineage exists — `has_later_dirty_evidence` orders on
`source_read_started_at` and falls back to `created_at` only when the fit never
recorded a source read. Introducing a new ordering column would leave that
fallback ungoverned rather than removing it. Freezing `created_at` on terminal
fits makes the fallback safe without changing freshness semantics.

`id` and `tenant_id` are also added: they select the row and correlate artifacts
and dirty lineage, so under the directive's broader dependency model (§21) they
are authority-bearing even though they never move in practice.

Registry: **28 → 31 columns.** `governed_exclusions` is empty.

### 8.2 Bidirectional derivation

`scripts/ci/_b25_p13_c7_dependency_derivation.py` resolves the projection's CTE
alias map and derives the real column set each relation contributes:

```text
public.bayesian_model_fits (31)
public.bayesian_artifacts   (8)
public.b24_dirty_events     (7)
```

The gate then asserts set equality in both directions, and additionally that the
non-fit decision inputs declared in the contract equal what the read model
actually consumes. An unresolvable reference is an error, not a silently ignored
one.

`NC-C7-S01` adds a `fit.foo` reference to the read model without registering it —
the exact direction C6 never checked — and the gate refuses.
`NC-C7-S02` removes `created_at` from governance while the read model still
orders freshness by it; the gate refuses.

### 8.3 Runtime mutation matrix

Static membership proves the registry *names* a column. Only execution proves the
database refuses to move it. `test_c7_every_governed_fit_column_is_frozen_when_terminal`
runs a two-phase matrix over all 31 governed columns:

- **Phase 1 — production configuration.** Both guards armed, no dispatch lease
  held. Every governed column must be refused. This is the operational claim:
  the mutation is impossible.
- **Phase 2 — terminal guard isolated.** The dispatch fence is suspended for one
  transaction so the terminal-truth guard is what is measured. Every governed
  column must be refused specifically by `b24_terminal_fit_truth_immutable`, so
  none is protected only by accident of the fence being in the way.

Building this matrix surfaced two facts worth recording, because both would have
made a weaker test pass for the wrong reason. The dispatch fence fires ahead of
the terminal guard and refuses identity mutations under its own error; and the
temporal-plausibility guard refuses future evidence timestamps ahead of the
terminal guard. Both are named explicitly in the matrix rather than absorbed.

### 8.4 Non-fit lifecycle governance (C7-M)

The directive was explicit that these must not simply be frozen forever —
artifact pruning is legitimate. The contract records, per relation, the mutation
authority, the legal transitions, the effect on historical envelopes and the
effect on new Trust reads. Enforcement:

| Guard | Refuses |
| --- | --- |
| `b24_enforce_artifact_lifecycle` | resurrection out of `pruned` / `rejected` |
| `b24_enforce_dirty_event_lifecycle` | mutating `observed_at`; leaving a terminal dirty status |

`test_c7_artifact_and_dirty_lifecycle_transitions_are_governed` proves that
`active -> pruned` **succeeds** (legitimate degradation) and that resurrection,
`observed_at` mutation and terminal-status reversal all fail with their specific
errors.

`observed_at` immutability was not theoretical: it caught a shortcut in this
report's own scheduler experiment, which had tried to simulate elapsed time by
rewriting `observed_at`. The experiment was rewritten to use real elapsed time
against a short real quiet period instead.

**C7-K: PASS. C7-L: PASS. C7-M: PASS.**

## 9. Exit Gate C7-N — Proof classification integrity

Report 41 established that 11 of C6's 13 "negative controls" were string or dict
substitutions fed to text-parsing validators — real regression guards, but not
behavioural proof. C7 does not attempt a larger count. It separates the two
kinds and refuses to let one stand in for the other.

```text
c7_invariant_groups_passed=7
c7_invariant_witnesses=120
c7_static_negative_controls_fired=18
c7_behavioral_obligations_bound=12
c7_behavioral_negative_controls_fired=0  # by design: behavioural falsifiers execute in the C7 physics suite
```

**STATIC (18 controls).** Appropriate where text *is* the invariant: generated-DDL
drift, registry membership, credential topology, workflow wiring, constant
agreement between the migration and the planner.

**BEHAVIORAL (12 proofs + 3 CI controls).** Everything about a running system.

### 9.1 A gate that does not run is not a gate

Found while verifying that the exact-main proof would actually execute: the P13

artefacts were listed**. An edit touching only the C7 gate, its derivation
library, its physics suite, or one of the manifests those controls read would
not have run the workflow at all -- every C7 control would have silently not
executed while the tree stayed green.

That is the same false-green class this corrective exists to remove, so it was
closed rather than recorded as a known gap. All C7 artefacts and read manifests
are now path-triggered, and `validate_proof_taxonomy` asserts each one appears
in the workflow's trigger block. `NC-C7-S18` removes one trigger path and the
gate refuses, so the gap cannot reopen silently.
