## 2. Pre-P1 Gate A: Canonical Revenue Extraction Standard

Canonical revenue law:
- Canonical amount basis: verified captured gross amount excluding processor fees.
- Canonical storage: integer minor units + ISO currency code.
- Binary floating-point use is forbidden in canonical storage, match arithmetic, discrepancy percentage arithmetic, refund/chargeback arithmetic, and test fixtures except explicit rejection/normalization tests.
- Provider extraction must use a **platform-keyed extraction registry**. Inline provider-specific amount field access inside match-kernel logic is forbidden.

## 3. Pre-P1 Gate A: Refund and Chargeback Concurrency Law

Required database physics:
- Refunds, chargebacks, reversals, and post-capture adjustments are append-only immutable revenue events.
- Provider-native event references require tenant-scoped idempotency.
- Duplicate provider-native event references are rejected at the database layer.
- Unsafe read-modify-write net revenue arithmetic is forbidden.
- Net verified revenue is derived from capture + committed adjustment-event aggregation, or materialized only under explicit lock/version controls.
- Two distinct concurrent partial refunds for the same order must persist exactly once each.

Semantically distinct adjustment events:
- `refund_partial`
- `refund_full`
- `chargeback_opened`
- `chargeback_won`
- `chargeback_lost`
- `reversal`
