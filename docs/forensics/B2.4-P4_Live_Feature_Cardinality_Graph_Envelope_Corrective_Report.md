- `channel`
- `currency`
- `provider`
- `campaign_or_feature`

`assert_profiled_dimensions_cover_model()` fails closed if an active dimension is not profiled by P4. `assert_candidate_dimensions_allowed_for_graph_build()` blocks future graph-build callers from requesting inactive or unprofiled dimensions.

## 8. Fallback and Graph Coupling

Feature-width fallback:

- `provider_count > B24_MAX_PROVIDERS` -> `feature_width_exceeded`
- `campaign_or_feature_count > B24_MAX_CAMPAIGNS_OR_FEATURE_KEYS` -> `feature_width_exceeded`

Graph-complexity coupling:

- Provider and campaign counts contribute to hierarchy levels, hierarchical group count, parameter count, logp terms, transform ops, symbolic-node estimate, tensor shape, and compilation-memory estimate.

Negative controls:

- Low-channel/high-campaign above feature cap fails with `feature_width_exceeded`.
- Low-row/high-campaign above hierarchy-level cap but below feature cap fails with `hierarchy_width_exceeded`.
- Provider/campaign count increases raise parameter, symbolic node, and compilation memory estimates.
