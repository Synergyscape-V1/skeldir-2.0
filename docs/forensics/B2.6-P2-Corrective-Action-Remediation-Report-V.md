**Q1. What class of defect does this directive exist to eliminate?**
Effect-class, not instances: *the system can believe THIS exact set of
values belongs to one authoritative execution when the values were
validated as independent memberships from different executions* — plus its
two consequence siblings: *`conducted` can become true without the governed
consequence existing*, and *published work can age forever while health
stays green*. Root cause in one line: operational state authorized by
caller convention rather than by one conserved execution identity and its
physically proven consequence.

**Q2. Where in the physical stack is that class made unavoidable?**
PostgreSQL constraints/triggers (composite UNIQUE + single-parent composite
FKs + write-time coherence + gate-clause transition law), the PostgreSQL
role-membership graph (unforgeable caller binding via `session_user` /
`current_user`, which `SET ROLE` cannot forge upward), dedicated login
roles with minimal grants (relay/beat cannot mint even if their code
tried), and a DB-derived staleness signal served by production health.
No invariant rests on application convention.

**Q3. What sovereign sources are composed with?**
PostgreSQL (UNIQUE/FK/trigger/RLS/role graph), the UTC day quantizer
(`app.core.day_window`, never reimplemented), the ingress event clock as
the window-membership sovereign, kombu/Celery result state as transport
only (never truth), and the existing validators/equivalence proofs as
oracles extended, not replaced.

**Q4. Sibling surfaces sharing each root cause?**
Outbox AND directory AND receipts (all children of D); dispatch window AND
directory window; API AND relay AND beat sharing one credential; conducted
via worker direct UPDATE AND via any app_user session; health via
housekeeping probe AND readiness AND liveness (all blind to
b23_match_engine); migration quarantine AND bootstrap lane AND downgrade

**Q5. Adversarial candidates constructed before submitting?**
