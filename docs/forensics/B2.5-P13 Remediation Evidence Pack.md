## 4. H00-B — `NC-P12-ISO-03` made real

Domain 17 named a control that was implemented nowhere. The deeper finding is
*why*: every other isolation control is a **text override** evaluated by static
analyzers, and a text override cannot make a module load. The control had no
mechanism it could be implemented in. Plane D reported completeness regardless,
because it only checked that the identifier string was non-empty.

The control now mutates a trust module on disk, runs the trace in a fresh
interpreter, and requires the forbidden load to be observed. Properties:

* the mutation is inserted after `from __future__` so the module stays
  syntactically valid — a control firing on `SyntaxError` proves the file
  stopped parsing, not that the invariant was detected (§43);
* restore is **byte-exact** (`read_bytes`/`write_bytes`); an earlier text
  round-trip perturbed line endings, and a control that edits the repository it
  observes is not a control;
* it is a **distinct defense** from the AST scan. An AST rejection proves a
  forbidden spelling was written; this proves a forbidden module was loaded.

`isolation_negative_controls_fired`: 3 → **4**.

The finding is subtler than a broken link. Those proofs **did** run — one hop

the recorded causal chain was fiction. That is exactly the directive's

### 9.2 H00-G — path coverage was non-causal

`_declared_trigger_paths` flattened trigger paths from every `b2_5-*.yml` into
one set, so a path counted as covered when *any* B2.5 workflow declared it.
Editing a canonicalization file could satisfy path-trigger integrity by way of an
unrelated broad workflow while the canonicalization proof never ran.

Relevance is now **derived from the registry itself** rather than maintained as a
second list: a path's relevant detectors are the validators of the invariants
whose `production_path` it matches. Coverage must come from a workflow that both
declares the path **and** invokes those detectors. A parallel hand-maintained
list would drift apart and reintroduce the defect it was meant to close.

`path_trigger_controls_passed`: 14 → **25**.

### 9.3 H00-H — detectors were not self-protecting

Weakening a validator is a change to *proof*, not to production code. A
path-filtered workflow that does not list the validator's own file will not run
it, so the weakened detector never gets the chance to notice its own weakening.
Reproduced: **3** validators unprotected.

`validate_detector_self_protection` requires every validator to be covered by its
own workflow's triggers. **22/22.**

Falsifier `NC-P12-CI-07` narrows **both** trigger events. An unfiltered
`pull_request` covers every path by construction, so a control that stripped only
the push path would leave the property satisfied and fire silently — the same
silent-control trap that caught `NC-P12-CI-01` during P12.

### 9.4 H00-E — runtime cases did not represent the claimed paths

The five cases were `sign`, `verify`, `export`, `tampered`, `unsupported` — all
cryptographic. None ran TrustEnvelope **construction**, which is where
confidence, money and reason-code semantics live, and therefore where a forbidden
Bayesian or LLM import is most plausible. Claiming "representative trust runtime
paths" on that basis inflated five counters into five semantics.

Added `builder_normal_read` and `builder_degraded_money_unavailable`. **5 → 7.**

The builder session is inert and raises on any access, so these paths are proven
not to touch the database. That is legitimate under §1273 because the property
under proof is *which modules load*, not database behaviour. Route-level and
RLS-level truth is owned by the P13 end-to-end harness against real PostgreSQL,
and is **not** claimed here.

### 9.5 One ordering correction

`validate_core` now runs existence → invocation → self-protection. The new
binding check was pre-empting `NC-P12-CI-03`, whose intended reason is
`invariant_validator_missing_on_disk`; a control firing for the wrong reason is a
control that no longer proves what it claims.

`ci_gate_negative_controls_fired`: 5 → **7**.

Real PostgreSQL at migration head, RLS active, the actual FastAPI route stack,
real `agent_clients` persistence, the production builder, the production signer,
and **public-only** verification. Mocking is permitted only where the mocked

### 13.4 The tamper set is derived, not listed

Load-bearing means `semantic_truth_v1`, `signature_material_v1`,
`derived_hash_field_v1` and `artifact_payload_v1`, read from the hash-domain
manifest. A hand-written list stops covering a field the moment the contract adds
one — exactly how a tamper suite becomes "complete" while blind. The 24
`display_only_excluded_v1` paths are out of scope by contract; demanding they be
mutation-sensitive would assert a property the design explicitly rejects.

83 manifest paths expand to 147 concrete locations because array paths address
every element. Tampering only the first would report the path as covered while
leaving the rest of the array unproven.

### 13.5 Negative controls bind to the gates, and the binding is proven

Eleven controls each construct a violating artifact and require the **gate's own
checker** to reject it. The checkers are extracted so gate and control run one
code path: a control that re-implements the check proves the control, not the
gate.

Meta-proof: neutering `_assert_confidence_not_fabricated` makes `NC-P13-04` stop
firing and the suite fails with `negative control did not fire: NC-P13-04`.
Restoring it passes. A control that keeps firing against a broken checker is not
a control.

`NC-P13-13` is deliberately inverted — its expected outcome is *stability*, not
rejection. P2 separates the identity domains precisely so key rotation cannot
restate truth, so it re-signs with a different key and recomputes the semantic
hash rather than comparing a copied field to itself.

### 13.6 Three vacuity defects found in this harness, by its author

Recorded because each passed while proving nothing, and each is the same defect
the P12 entry gate existed to close:

1. **G1 money assertion.** Demanded a readable `*_minor` field. The envelope
   commits the integer through the provenance chain into `semantic_truth_hash`
   and deliberately never republishes it, so the assertion would have flagged
   correct code as broken.
2. **G5 prompt-control.** Asserted hostile strings were absent from authority
   fields while no hostile string had ever been seeded. It now requires the
   adversarial text to actually reach the envelope before asserting where it may
   not appear.
3. **Six negative controls.** Constructed a violation and then asserted the
   violation existed — self-fulfilling. They now call the gate's own checker and
   require an `AssertionError`.

A fourth was caught by the layer rather than by inspection: the G11
failure-masking scanner originally spelled its tokens literally, which placed
`continue-on-error: true` inside a `b2_5-*.yml` file. P12's Plane D scans exactly
those files for exactly those strings and went red. The detector introduced the
defect it detects. Tokens are now assembled from parts.
