# B1.4-P4 Remediation Evidence Pack (Corrective Closeout)

Date: 2026-03-22  
Scope: B1.4-P4 Retention + Deterministic Deletion Semantics (follow-up corrective pass)

## 1) Corrective Status Snapshot

This pass closes the previously open P4 blocker space by:

- moving privacy erasure audit artifacts off `attribution_events` and into a dedicated append-only `compliance_audit_ledger`,
- replacing unindexed JSONB deletion selectors with explicit index-backed lookup columns/paths,
- removing `session_authority` delete+placeholder reinsertion and replacing it with deterministic in-place invalidation semantics,
- hardening split-substrate lookup/index mechanics (`lookup_hash`, GIN + tenant/indexed selectors),
- widening P4 merge-blocking enforcement and runtime proofs for the corrected invariants.

## 2) Validated/Refuted Hypothesis Ledger

### H01 - `privacy_tombstone` still lives on wrong physical surface
Status: **Validated pre-fix, remediated**

Pre-fix evidence:
- `backend/app/tasks/privacy.py` inserted `event_type='privacy_tombstone'` rows into `attribution_events`.
- No dedicated `compliance_audit_ledger` existed.

Remediation:
- Added `compliance_audit_ledger` substrate (migration + model + RLS + append-only trigger).
- Privacy worker now writes erasure artifact into `compliance_audit_ledger`, not `attribution_events`.

### H02 - Tombstone insertion caused side-effect risk (trigger/report contamination)
Status: **Validated pre-fix, remediated**

Pre-fix evidence:
- Tombstones inserted into `attribution_events` could trigger normal ledger insert side effects.

Remediation:
- Removed tombstone insertion into `attribution_events`.
- Deterministic deletion now emits immutable audit artifact in `compliance_audit_ledger` only.

### H03 - Deletion target resolution under-specified for scale
Status: **Validated pre-fix, remediated**

Pre-fix evidence:
- `raw_payload->>'idempotency_key'` selector path in privacy worker for dead-event redaction.
- No `lookup_hash` or GIN hardening on `raw_event_payloads`.

Remediation:
- Added `raw_event_payloads.lookup_hash` (SHA-256 of idempotency key) + tenant/indexed lookup.
- Added `idx_raw_event_payloads_payload_json_gin`.
- Added `dead_events.idempotency_key` and `dead_events_quarantine.idempotency_key` + tenant/indexes.
- Privacy worker now uses indexed `idempotency_key`/`correlation_id` columns (no JSONB extractor selector dependency).

### H04 - Placeholder session-authority reinsertion workaround remains
Status: **Validated pre-fix, remediated**

Pre-fix evidence:
- Privacy worker deleted `session_authority` rows and reinserted invalidated placeholders.

Remediation:
- Removed placeholder reinsertion flow.
- Privacy worker now deterministically invalidates in-scope `session_authority` rows in-place (`invalidated_at`, reason, issuer, bounded expiry), preserving FK integrity without latent active capability.

### H05 - Split-substrate finality incomplete
Status: **Partially validated pre-fix, remediated to P4-correct boundary**

Pre-fix evidence:
- Erasure tombstone semantics wrote payload back into immutable ledger.

Remediation:
- Audit artifact removed from immutable attribution ledger.
- Privacy-bearing mutable envelopes are now erased/redacted on mutable substrates while immutable attribution facts remain append-only.

### H06 - Existing proof lane blind to corrected blocker surfaces
Status: **Validated pre-fix, remediated**

Remediation:
- Widened P4 enforcer (`scripts/ci/enforce_b14_p4_retention_deletion.py`) to bind:
  - dedicated audit ledger presence,
  - lookup hardening tokens/indexes,
  - no tombstone-in-ledger/privacy placeholder reinsertion patterns,
  - corrected runtime proof signatures.
- Runtime suite expanded with index-backing proof test.

- Privacy deletion audit artifacts now persist in append-only `compliance_audit_ledger`.
- `compliance_audit_ledger` protections:

## 6) Explicit Deletion Lookup/Index Strategy

- Attribution-event targeting:
  - indexed selectors on `attribution_events.idempotency_key` and `correlation_id`.
- Raw payload targeting:
  - `raw_event_payloads` join via immutable `event_id`,
  - `lookup_hash` for deterministic selector hashing path,
  - indexes:
    - `idx_raw_event_payloads_tenant_lookup_hash`,
    - `idx_raw_event_payloads_payload_json_gin`,
    - existing `idx_raw_event_payloads_tenant_created`.
- Dead-event targeting:
  - normalized `idempotency_key` columns on `dead_events` and `dead_events_quarantine`,
  - indexes:
    - `idx_dead_events_tenant_idempotency_key`,
    - `idx_dead_events_quarantine_tenant_idempotency_key`.
- Critical removal:
  - privacy worker no longer depends on unindexed `raw_payload->>'idempotency_key'` selectors.

## 7) Placeholder Resolution

- Removed delete+placeholder reinsertion from privacy worker.
- Replaced with deterministic `session_authority` invalidation updates.
- Runtime proof confirms:
  - no active authority row remains,
  - invalidated authority exists,
  - no `issued_by='privacy_erasure_tombstone'` placeholder rows.

## 8) Final Split-Substrate Lifecycle Model

- Immutable substrate:
  - `attribution_events` (append-only financial/attribution facts).
- Mutable/expirable/erasable substrate:
  - `raw_event_payloads` (90-day hard-delete GC),
  - `dead_events` + `dead_events_quarantine` raw/error envelope redaction,
  - `session_authority` capability invalidation on deterministic erase.
- Immutable privacy compliance evidence:
  - `compliance_audit_ledger` append-only artifacts.
