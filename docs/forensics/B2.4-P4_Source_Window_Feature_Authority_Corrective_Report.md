## 6. New Feature Authority Schema

Table: `public.b24_source_window_feature_authority`

Key:

```text
tenant_id
model_type
model_version
source_window_start
source_window_end
source_snapshot_hash
```

Counts:

```text
channel_count
currency_count
provider_count
campaign_or_feature_count
```

Freshness:

```text
freshness_status IN ('fresh', 'stale', 'mismatched')
policy_version
computed_at
```

The migration enables and forces tenant RLS and grants only bounded read/write access to runtime roles.

## 7. Source Identity and Freshness

P4 performs a single lookup by exact `tenant_id/model_type/model_version/window/source_snapshot_hash`. Approval requires:

- exact row exists;
- `freshness_status = 'fresh'`;
- `policy_version = B24_RESOURCE_POLICY_VERSION`.

Missing rows fail closed with `cardinality_authority_missing`. Related rows for the same tenant/window but different snapshot fail closed with `cardinality_authority_mismatch`. Non-fresh rows or stale policy versions fail closed with `cardinality_authority_stale`.

## 8. Async Lag Safety

If a new campaign/provider arrives after authority computation but before P4 evaluation, P2 hashes a different source snapshot. P4 then cannot find a matching authority row, or finds a related row with a different hash, and persists a non-dispatchable fallback before claim/outbox.

## 9. Maintenance Path and Ingress Safety

`upsert_source_window_feature_authority()` writes one bounded rollup row by tenant/window/model/version/snapshot. It is not called by the P4 planner to discover features and does not query raw source tables. The write is scoped by the primary key and uses `ON CONFLICT ... DO UPDATE`, avoiding synchronous full-window deduplication or hot counter increments in deterministic ingress.

## 10. Privacy and Deterministic Truth

The authority table stores count integers plus tenant/window/model/snapshot metadata. It does not store raw campaign names, provider tokens, customer identifiers, raw payloads, or identity-table material. P4 reads deterministic truth through P2 snapshotting and writes only Bayesian fit fallback metadata or the derived authority table.

## 11. Feature and Graph Coupling

`build_input_profile_from_preflight()` now requires `SourceWindowFeatureAuthority`. Authority counts feed:

- `feature_width_exceeded` checks for channel/currency/provider/campaign caps;
- design matrix column estimates;
- tensor shape and tensor element estimates;
- graph formulas for hierarchy levels, parameter count, symbolic nodes, logp terms, transform ops, and compilation memory.

Low-channel/high-campaign candidates still fail `feature_width_exceeded`. Low-row/high-feature candidates still fail graph/hierarchy complexity before graph construction or dispatch.

## 12. Pre-Dispatch and Lease Safety

Planner order is now:

```text
acquire preflight lease
compute P2 source snapshot
load snapshot-fresh feature authority
if authority missing/stale/mismatched: persist fallback and terminalize lease
evaluate P4 resource/graph envelope
only then claim fit and create dispatch outbox
```

Authority failures use `upsert_feature_authority_fallback_from_snapshot()` and never create a dispatch outbox row. Fallback persistence clears `sampling_started_at`, `last_fit_at`, runtime/diagnostic/artifact fields, and terminalizes the preflight lease.

## 13. Validator Hardening

Negative controls are non-vacuous and pass.
