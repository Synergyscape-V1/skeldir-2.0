## 3. Runtime and contract remediation

The mounted surface is:

```text
GET  /api/trust/v1/envelopes/{subject_type}/{subject_ref}
POST /api/trust/v1/envelopes/query
POST /api/trust/v1/verify
GET  /api/trust/v1/keys/jwks             (public P8 surface preserved)
```

The envelope routes require `trust.envelope.read`; hosted verification requires `trust.envelope.verify`. The route obtains an RLS-bound machine session from `X-Tenant-ID` without invoking human JWT/RBAC dependencies. Issuance composes the P5 builder with the P7 durable audit seam and the P8 signer. Verification uses the active plus historical public-only registry.

Runtime private signing authority is loaded only from deployment-secret environment variables. The 32-byte Ed25519 seed is never persisted or returned. The JWKS route publishes the active public key when configured and retains the prior P8 public registry as a safe pre-configuration fallback.

The first protected-PR matrix exposed a runtime-image dependency boundary that
the dedicated P10 workflow had masked by installing validator dependencies:
mounting the route imports the P2 JSON Schema validator, but `jsonschema` was
not declared in `backend/requirements.txt`. The dependency is now explicit in
the runtime image, and a clean container import proves that the full FastAPI
application mounts all routes successfully.

P10 uses the P7 `access_log_only=True` mode. Therefore a read produces the directive-authorized Tier A `trust_access_log` write but not issuance, denial, replay, fit, task, or artifact writes. Existing P7 callers retain companion-event behavior by default.

## 4. Rate-limit correction

The P9 hot path now computes a stable bucket:

```text
bucket_epoch = floor(unix_seconds / window_seconds) * window_seconds
window_start = UTC(bucket_epoch)
window_end   = window_start + window_seconds
```

It then executes exactly one atomic statement:

```sql
INSERT INTO public.trust_rate_limit_state (...)
VALUES (..., 1, ...)
ON CONFLICT (tenant_id, agent_client_id, window_started_at, window_ended_at)
DO UPDATE SET request_count = trust_rate_limit_state.request_count + 1, ...
RETURNING request_count;
```

There is no SELECT check and no `SELECT ... FOR UPDATE` in the rate-limit function.

The real PostgreSQL storm falsified one final implementation assumption before
publication: asyncpg does not accept ISO strings for bound `timestamptz`
parameters. Passing the timezone-aware bucket `datetime` values directly fixed
the driver boundary. The same 50-request proof then passed with exactly 10
admissions, one persisted bucket row, and a final persisted count of 50.
