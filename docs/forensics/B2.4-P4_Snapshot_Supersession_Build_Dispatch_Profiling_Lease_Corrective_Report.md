## 3. Supersession Strategy

Path A plus Path B.

`backend/app/bayesian/snapshot_supersession.py` enforces a deterministic dominance rule before claim/outbox:

```text
For the same tenant/model/version/window, frozen Hash A is superseded if a different snapshot hash has already become the active execution owner, produced a queued/running/succeeded fit newer than A's lineage timestamp, or produced a pending/dispatching/dispatched outbox row newer than A's lineage timestamp.
```

Superseded Hash A is marked `authority_retry_superseded`, creates no dispatchable outbox, and releases/terminalizes preflight/profiling state.

## 4. Build Dispatch Strategy

Path C.

`request_feature_authority_build()` now commits two coordinated facts in one SQL statement:

- `b24_feature_authority_build_requests`: idempotent build intent by tenant/model/version/window/`source_snapshot_hash`.
- `b24_feature_authority_build_outbox`: idempotent dispatch intent by the same key plus `dispatch_key`.

`dispatch_due_feature_authority_builds()` leases due rows with `FOR UPDATE SKIP LOCKED` and publishes the bounded task payload for `app.tasks.bayesian.build_feature_authority`.

## 5. Profiling Lease Strategy

Path E.

`backend/app/bayesian/profiling_lease.py` adds a hash-scoped profiling lease:

```text
tenant_id
model_type
model_version

```

Only the lease holder may validate feature authority, run feature-width checks, run graph/resource envelope math, or transition to P3 claim/outbox.

## 7. Previous Frozen Retry Gap

Before this correction, authority reactivation could preserve `source_snapshot_hash`, but the planner still grouped candidates at window level, recomputed latest P2 before frozen authority validation, had no explicit newer-snapshot dominance rule, and had no pre-P4 hash-scoped profiler lease.

## 8. New Snapshot Supersession Policy

Hash A remains frozen and source-snapshot scoped. Before P3 claim/outbox, Hash A is rejected as superseded if Hash B has already:

- become active owner in `b24_active_execution_leases`;
- produced a queued/running/succeeded `bayesian_model_fits` row newer than A lineage;
- produced a pending/dispatching/dispatched `b24_fit_dispatch_outbox` row newer than A lineage.

## 9. Hash A / Hash B Lifecycle Separation Proof

`lease_debounced_dirty_candidates()` now groups and leases by `source_snapshot_hash`, using `IS NOT DISTINCT FROM` joins. Null-hash normal dirty events remain separate from authority retry/fresh rows scoped to Hash A or Hash B.

`assert_snapshot_artifact_not_regressing_current_output()` calls the same supersession policy and raises if older Hash A would publish artifact or TrustEnvelope current output behind newer Hash B.

## 12. Authority Build Dispatch Mechanism

`b24_feature_authority_build_outbox` stores source-snapshot-scoped dispatch intent with status, attempt counters, `next_attempt_at`, and dead-letter fields. Due rows are leased in bounded batches.

## 13. Transactional Outbox Proof

`UPSERT_AUTHORITY_BUILD_REQUEST_SQL` uses one CTE:

```text
WITH upserted_request AS (... b24_feature_authority_build_requests ...)
queued_dispatch AS (... b24_feature_authority_build_outbox ...)
SELECT ... FROM upserted_request
```

This prevents DB/broker split-brain by publishing only after durable outbox leasing.

## 14. Build Dispatch Idempotency Proof

The outbox has unique constraints on tenant/window/snapshot candidate identity and tenant/dispatch key. Duplicate planner attempts upsert one effective build job.

## 15. Build Dispatch Latency/SLA Proof

The due index `idx_b24_feature_authority_build_outbox_due` covers tenant, status, `next_attempt_at`, and id. Dispatch batches are bounded by `DEFAULT_AUTHORITY_BUILD_DISPATCH_BATCH_SIZE=25`.

## 16. Pre-P4 Profiling Lease Design

`b24_p4_profiling_leases` is keyed by tenant/model/version/window/`source_snapshot_hash`. It records owner, TTL, attempt count, terminal reason, and stale recovery.

## 17. One-Profiler-Per-Candidate Proof

`acquire_profiling_lease()` uses the hash-scoped primary key and `ON CONFLICT` stale recovery. Duplicate non-stale contenders return `acquired=False` and exit before authority validation and P4 envelope math.

## 18. Duplicate `feature_authority_fresh` Proof

Duplicate reactivation rows may be leased, but only one planner can acquire the hash-scoped profiling lease for the candidate. Others suppress without profiling.

## 19. Profiling Lease Cleanup Proof

`terminalize_profiling_lease()` is called on:

- authority failure: `profile_failed`;
- resource/graph rejection: `profile_rejected`;
- supersession/source hash change: `profile_superseded`;
- success transition to claim path: `profile_passed`.

## 20. Frozen Hash A No-Latest-P2 Regression Proof

For retry candidates with `candidate.source_snapshot_hash`, the planner validates feature authority for the frozen hash before `compute_source_snapshot_hash()` is called. If the later P2 hash differs, Hash A is marked superseded and never dispatches.

## 21. P4 Envelope Preservation Proof

Fresh, non-superseded retries still call `evaluate_source_snapshot_resource_bounds()` before `claim_fit_for_snapshot()`. Existing feature-width and graph-complexity tests remain green.

## 22. P3 Claim/Outbox Compatibility Proof
