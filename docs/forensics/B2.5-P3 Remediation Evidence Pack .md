## Initial Findings

H-P3-01 was confirmed: TrustEnvelope string fields had no complete text trust taxonomy. Remediation added an explicit registry covering 89 string-bearing schema paths with no default-safe fallback.

H-P3-02 was confirmed: no total trust-class/content-risk-class matrix existed. Remediation added 7 trust classes, 10 content risk classes, and 70 matrix cells, with missing-cell and duplicate-cell controls.

H-P3-03 was confirmed: there was no runtime control proving provider text could not target machine-authority fields. Remediation rejects provider-controlled strings for machine authority enum/code/system fields regardless of detected risk.

H-P3-04 was confirmed as a risk: the boundary could be confused with prompt-injection detection. Remediation documents and tests finite known instruction indicators only; field-class enforcement is the authority boundary.

H-P3-05 was confirmed as a CI risk: a single literal fixture could have satisfied superficial checks. Remediation uses input families, variants, mutation-style negative controls, and anti-hardcoding scans.

H-P3-06 through H-P3-09 were confirmed as unvalidated: delimiter/markup/tool-like strings, safe printable display labels, opaque provider references, and NUL/control/bidi/invalid inputs had no falsifiable P3 disposition layer. Remediation added deterministic quarantine/display/HMAC behavior and desync prevention tests.

H-P3-10 and H-P3-11 were treated as regression risks. P1/P2 validators still pass, and scope controls block routes, builders, signing/JWKS, agent auth, audit tables, exports, MCP, DB/network/LLM coupling, and action authority.
