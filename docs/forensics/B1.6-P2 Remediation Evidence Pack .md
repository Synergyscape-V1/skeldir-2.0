## 1) Initial Findings (Validated on `main`)

- `backend/app/llm/provider_boundary.py::SkeldirLLMProvider.complete` was still transport/cache oriented and could return success with unvalidated provider output.
- Cache replay (`_cache_hit`) returned `llm_semantic_cache.response_text` directly with no read-time validation.
- No deterministic normalization/extraction existed before schema parsing.
- No machine-checkable output validation taxonomy existed at the boundary.
- Worker/API downstreams were still receiving raw boundary `output_text` as the effective parse authority.
- CI had B1.6-P1 enforcement, but no dedicated B1.6-P2 malformed-output/cache-replay validation gate.

## 2) Remediations Implemented

### 2.1 Generic upstream-supplied schema binding (all active surfaces)

Added `backend/app/llm/output_validation.py`:

- explicit schemas for `route`, `explanation`, `investigation`, `budget_optimization`
- generic `ProviderOutputValidationSpec`
- endpoint->spec registry (`VALIDATION_SPECS_BY_ENDPOINT`)
- typed `OutputValidationResult`

Worker layer now supplies validation contract upstream into boundary:

- `backend/app/workers/llm.py`
  - `_ENDPOINT_VALIDATION_SPECS`
  - `_validation_spec(...)`
  - every `_PROVIDER_BOUNDARY.complete(...)` call passes `validation_spec=...`

This preserves boundary genericity: no investigation/budget domain service imports were added to `provider_boundary.py`.

### 2.2 Deterministic normalization/extraction + fail-closed validation kernel

`backend/app/llm/provider_boundary.py` now validates at the boundary with:

- deterministic normalization/extraction (`markdown_fence_json`, `raw_json`, `embedded_json`, `plain_text`)
- schema validation via upstream-provided spec
- fail-closed classification:
  - `normalization_failed`
  - `schema_failed`
  - success only when validated
- typed result fields on boundary return:
  - `validation_code`
  - `validation_stage`
  - `validated_output`

Success path now emits normalized/validated text only.

### 2.3 Cache replay re-validation and invalid-cache miss semantics

On cache hit:

- cached payload is re-validated before reuse
- invalid cache payload is marked invalid (`watermark` bump + metadata flag) and bypassed
- request continues through fresh provider path
- no direct 500/fail-open cache-hit return

### 2.4 Validation outcome sink wiring at boundary

Boundary now writes structured validation failures to `llm_validation_failures` for:

- cache validation failures
- provider output normalization/schema failures

### 2.5 P2 CI adjudication wiring

Updated `.github/workflows/ci.yml` with:

- `Run B1.6-P2 canonical validation kernel gate`
- executes `pytest -q backend/tests/test_b16_p2_validation_kernel.py`
- artifacts to `artifacts/b16-p2/b16_p2_kernel_proofs.log`

## 3) New/Updated Tests

Added `backend/tests/test_b16_p2_validation_kernel.py` covering:

- schema binding coverage for all active LLM surfaces
- deterministic normalization:
  - markdown-fenced JSON acceptance
  - malformed JSON -> `validation_normalization_failed`
  - structurally invalid JSON -> `validation_schema_failed`
- cache-invalid replay path:
  - invalid cached payload is invalidated/bypassed
  - fresh provider generation occurs
  - success remains validated
- boundary sink protection:
  - invalid investigation output blocked before durable success sinks
- structured sink proof:
  - validation failures inserted into `llm_validation_failures`
