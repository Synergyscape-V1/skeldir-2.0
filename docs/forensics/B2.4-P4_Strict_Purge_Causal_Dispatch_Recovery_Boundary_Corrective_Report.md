`request_feature_authority_build` still creates the build request and `b24_feature_authority_build_outbox` row transactionally. Normal dispatch no longer waits for due-row polling.

## 10. Build Task Registration Proof

- `app.tasks.bayesian.dispatch_feature_authority_build`
- `app.tasks.bayesian.build_feature_authority`

The dispatcher leases the exact committed outbox row by dispatch key, publishes the build task, and marks the outbox dispatched or retryable/dead-lettered on publish failure. The build task reactivates matching frozen waiters when snapshot-fresh authority exists, otherwise leaves the request in bounded `authority_waiting`.

## 11. Recovery-Only Sweeper Boundary

Constants:

- `NORMAL_DISPATCH_DEADLINE_MS = 5000`
- `RECOVERY_ORPHAN_THRESHOLD_MS = 60000`
- `MAX_DISPATCH_ATTEMPTS = 5`
- `DISPATCH_RETRY_BACKOFF_MS = 30000`

Sweeper eligibility is limited to:

- pending rows older than `RECOVERY_ORPHAN_THRESHOLD_MS`;
- `failed_retryable` rows whose `next_attempt_at` is due;
- `stale_recovered` rows whose `next_attempt_at` is due.

Fresh pending rows are ignored.
