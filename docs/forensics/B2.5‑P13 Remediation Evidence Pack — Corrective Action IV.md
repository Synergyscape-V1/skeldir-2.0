## IV.5 Producer and Transaction Proof

The machine‑generated inventory covers `fit_claim.py`, every success and terminal failure branch in `fit_execution.py`, repository claim/fallback/resource paths, migrations, and test‑only privileged fixtures. Its governing rules are:

- source snapshot start/end are captured by PostgreSQL `clock_timestamp()` inside the transaction that computes the snapshot;
- claim/repository persistence carries both times with `source_snapshot_hash`;
- success writes classification, evidence hash, four frozen integer fields, and classification time together;
- timeout, worker loss, resource failure, fallback, cancellation, artifact failure, and other unavailable terminal paths clear partial measured evidence;
- PostgreSQL is the final commit fence even if a future buggy writer bypasses a repository helper;
- Trust performs no write, fit, dispatch, live financial recomputation, or LLM call.

The C4 producer negative control replaces the success‑path evidence hash bind with `NULL`; the inventory gate fails. The runtime transaction control then demonstrates rollback, so static inventory and physical atomicity prove distinct properties.
