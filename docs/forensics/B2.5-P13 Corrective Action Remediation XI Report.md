## 2. Baseline reproduction — the falsifier before the patch

The handoff note said the baselines were confirmed and should not be re-run. The
directive says the opposite in §4 and §67: *treat every hypothesis as unvalidated
against the state you begin from*, and *do not patch before preserving a precise
executable falsifier*. The directive is the authority, the reproduction takes
minutes, and the negative control needs the harness regardless. So it was
re-run.

**H-C11-01, reproduced on current protected main**, against a database migrated
from that lineage, using the roles CI provisions:

```
app_worker + tenant A, no publisher GUC     -> 1 row   (tenant A only)
app_worker + tenant A + publisher GUC       -> 2 rows  (BOTH tenants)
app_worker, NO tenant GUC at all            -> 2 rows  (BOTH tenants)
app_worker cross-tenant UPDATE              -> UPDATE 1
app_worker cross-tenant DELETE              -> refused (table grant, not RLS)
```

The mechanism, read from `pg_policy` on the live database: all seven policies on
`b24_fit_dispatch_outbox` are permissive, and
`initial_dispatch_publisher_b24_fit_dispatch_outbox` is `FOR ALL` with no tenant
predicate, keyed on `session_user = 'app_worker'` plus a GUC. PostgreSQL ORs
permissive policies, so satisfying that one is unconditionally sufficient.

The principal the policy authorises is the principal permitted to set the GUC.
The capability is self-issued: the session proves its own authority.

Note the sibling recovery policies on the same table are split `SELECT`/`UPDATE`.
The least-privilege pattern was already present beside the policy that abandoned
it.

## 4. Remediations, by causal property

### 4.1 The publisher is a different principal

The GUC-keyed policy is dropped. Two policies replace it, keyed on
`session_user = 'app_dispatch_publisher'`: one `SELECT`, one `UPDATE`. No
`INSERT`, no `DELETE` — the publisher's actual state transition is select-and-
lease, and nothing more is granted.

Database identity, not caller convention, because an application call-stack rule
cannot constrain a PostgreSQL principal that can issue the same `SET` itself.
The publisher task authenticates on its own DSN and runs on its own queue
(`bayesian_publisher`), so an execution worker cannot acquire the capability by
consuming from the same queue.

**After, same three sessions:**

```
app_worker + tenant A + publisher GUC       -> 1 row   (tenant A only)
app_worker, NO tenant GUC at all            -> 0 rows
app_worker cross-tenant UPDATE              -> UPDATE 0
app_dispatch_publisher                      -> 2 rows  (legitimate global capability)
```

### 4.2 A policy identifier denotes one set of semantics

A versioned semantic registry binds each identifier to the governed numbers it
denotes, with a component digest per policy and one bundle hash over the tuple.
Changing semantics without a version transition changes the digest and fails
closed; the gate goes red rather than producing an identical hash.

The registry seed lives in the migration **as data**. A migration that computed
its seed from live policy modules would write whatever those modules said on the
day it ran, so a fresh database and an existing one could disagree about what an
identifier meant — the exact drift the registry exists to prevent.

### 4.3 The bundle is recomputed, not trusted

Trust recomputes the digest from the versions persisted beside it and compares,
before signing. Presence and shape checks are not correspondence checks.

The two fixtures that shipped inconsistent bundles are corrected rather than
exempted.

### 4.4 Replan lineage is append-only

`b24_fit_policy_replan_lineage` records every transition — tenant-isolated,
insert-only by trigger, `UPDATE`/`DELETE` refused outright — committed in the
same transaction as the mutation it describes. A scalar previous-value column was
being used to represent an event history; those are different information
structures.

### 4.5 Provenance is claim-time authority

All four identities, the bundle hash and the authorised topology are stamped when
the fit is claimed. The runtime binding refuses to sample unless the executing
runtime is that regime. The replan path is the one place a not-yet-started fit
moves between regimes, and it leaves lineage.

Completion no longer restates any of it. Writing the same values again added
nothing and made any row whose claim differed by one field look like a policy
change mid-execution — which C11 refuses, correctly, because that is what it
would be.

### 4.6 Worker and sampler child resolve one runtime

The three deadline variables join the child environment allowlist, so the child
resolves what the worker resolved rather than module defaults.

## 5. What the gates caught that the audits did not

Recorded because each was found by a gate refusing something, not by reading.

- **The shipped image could not import its own execution path.** The artifact gate
  failed inside the container on a missing `temporal-policy.v1.yaml`.
  `fit_execution` imports `classify_confidence`, which reads that contract at
  module import, and the image never carried `contracts/`. It stayed invisible
  while nothing in CI exercised the real worker import graph inside the image —
  the exact class of gap C11 exists to close.
- **A green journey reported as failed.** The C11 production-worker gate ran the
  positive-confidence journey through the real Celery worker, passed in 15
  seconds, and then exited 141: `docker logs | grep -q` SIGPIPEs the writer under
  `pipefail`. A proof that passes and reports failure is as dangerous as the
  inverse, because the obvious reading is that the gate does not work.
- **A negative control reporting a defect it had just removed.** The semantic-
  mutation control mutates a policy constant, confirms red, restores, confirms
  green. All three mutations turn it red. The confirming run was failing with the
  mismatch it had undone: CPython invalidates bytecode by source mtime at
  one-second granularity, so a mutate-and-restore inside the same second leaves
  the mutated `.pyc` authoritative.
- **A stale hand-maintained deferral list.** R2 applies the canonical schema to a
  bare database, deferring eleven named B2.4 functions past the tables because a
  `LANGUAGE sql` body is resolved at create time. The new lineage function was
  not on that list. It is now plpgsql, which removes the ordering dependency at
  the source rather than extending a list that will be stale again.
- **An RLS coverage rule that would have widened authority.** The B0.4 security
  probe requires four-command policy coverage on every tenant-scoped table. The
  lineage table carries two, because `UPDATE` and `DELETE` are refused by trigger.
  Adding the missing policies to satisfy a coverage count would grant authority
  the table exists to withhold. The probe's existing one-table carve-out is now a
  named append-only set with the reason recorded.

## 8. What is not claimed

- **The registry records semantics, not correctness.** It guarantees that one
  identifier denotes one set of numbers and that a change of numbers is a change
  of identity. Whether those numbers are the right ones is a modelling question
  it does not answer.
- **Publisher least privilege is scoped to the dispatch outbox.** The dedicated
  principal holds `SELECT` and `UPDATE` there and nothing else, which is what its
  task needs today. A future publisher responsibility would require this revisited
  rather than assumed.
- **Two P9 broker-backed tests and the P12 RSS measurement do not run on the
  development machine** used here — no local broker, and `peak_rss_bytes` is a
  POSIX measurement. Both pass in CI, and CI is the authority for them.
- **Audit 48's flagged non-blocking defects are not all closed.** The
  publish-before-commit ordering in the fresh publisher and the fresh/recovery
  eligibility-window overlap are real, were reported as liveness rather than
  integrity defects, and the directive's §67 explicitly directs effort away from
  them until the authority defects are closed. They remain open and are recorded
  here rather than quietly dropped.
- **`assignment_generation` is still a dead fencing field**, written in four
  places and read nowhere. Audit 48 found it; it is inert rather than broken, and
  closing it was not part of this corrective's authority scope.
