## 8. Hypothesis ledger — H-P11-C3-01 … H-P11-C3-10

### H-P11-C3-01 — active default CSV violates P11-G4

**Status: CONFIRMED** (source tier).

* **Governing invariant.** P11-G4: CSV/XLSX display exports must contain
  `envelope_ref` or a non-authoritative display label.
* **Observed production behavior.** `export.py` defined
  `LEGACY_CSV_SCHEMA_VERSION = "legacy-v1"` and both `export_revenue` and
  `export_csv` declared `Query(default=LEGACY_CSV_SCHEMA_VERSION)`.
  `_legacy_csv_from_rows()` wrote exactly
  `("date","channel","revenue","conversions","confidence")` with no authority
  column, at media type `text/csv`.
* **Discriminating experiment.** Issue the default request with
  `csv_schema_version` omitted; retain only the response body; discard URL,
  query, headers, and media type. Ask whether the artifact states its own
  authority class.
* **Root cause.** RC-P11-01/RC-P11-04 confirmed: positional backward
  compatibility was treated as outranking P11-G4, and the conflict was resolved
  inside a local compatibility policy instead of at the version/surface
  lifecycle level.
* **Remediation.** `b25-p11-export-csv-compat-v1` becomes the default: legacy
  columns at indices 0–4 unchanged, `projection_authority` and
  `projection_schema_version` appended at 5–6. `legacy-v1` retired behind a
  governed 410. `b25-p11-export-csv-v2` untouched.
* **Negative control.** NC-C3-01 (strip authority columns from the default
  profile) and NC-C3-02 (point the default at the retired profile).
* **Remaining uncertainty.** Consumers asserting an exact column *count* rather
  than reading by index will observe a change. This is explicit, versioned,
  contract-declared, and carries a runtime migration path.

### H-P11-C3-03 — artifact protocol meaning changed without version identity changing

**Status: CONFIRMED** (empirically, not merely by source reading).

* **Observed.** Pre-PR619 `_artifact_identity_bytes` framed seven fields
  including `signing_key_id` and `signing_algorithm`; post-PR619 framed five,
  excluding both. `export_artifact_signature_material` changed from
  `DOMAIN || artifact_hash` to `DOMAIN || frame(hash) || frame(kid) || frame(alg)`.
  Both declared byte-identical `b25-p11-export-artifact-v1` /
  `b25-p11-artifact-framing-v1`.
* **Required discriminating experiment (directive §7), executed against
  `origin/main@b9a614d75`.** A valid artifact was constructed under exact
  pre-PR619 semantics (old framing, old signature material, valid active key,
  unchanged v1 markers) and passed to main's verifier:

  ```text
  markers:             b25-p11-export-artifact-v1 / b25-p11-artifact-framing-v1
  verification_status: rejected
  reason_code:         artifact_hash_mismatch
  ```

  A legitimately signed artifact whose declared version never changed was
  rejected as ordinary corruption. This is Model C — neither preserved nor
  explicitly retired.
* **Remediation.** Model A + explicit versioning. v1 frozen with its original
  framing and signing domain, `support_status: verification_only`,
  `issuable=False`. v2 introduced for the corrected signer-independent identity
  with its own domain `skeldir:b25-p11:export-artifact:v2\0`. Verification
  dispatches on the version tuple before touching any framing.
* **Post-fix observation.** The same historical artifact now verifies:
  `verification_status=verified`, `reason_code=None`
  (`test_historical_v1_artifact_verifies_through_its_own_protocol`).
* **Negative controls.** NC-C3-03 (collapse v1 onto the v2 algorithm),
  NC-C3-04 (remove historical framing), NC-C3-05 (mislabel new protocol as old).

### H-P11-C3-05 — global error-model checker trusts self-attested provenance

**Status: CONFIRMED.**

* **Observed.** `scripts/contracts/check_error_model.py::response_is_valid`
  returned `True` unconditionally when `x-skeldir-shared-error-component` was
  `True`, before any `$ref` or RFC 7807 structural check. `main()` runs
  `check_file()` over every `*.bundled.yaml` — a repository-wide, unscoped
  escape hatch, already load-bearing for P11's own 503.
* **Root cause.** Confirmed hypothesis 1: bundling dereferences `$ref`, and
  `VALID_RESPONSE_REF_PREFIXES` only matches pre-bundle documents, so the
  provenance the validator relied on was destroyed by the bundler. The boolean
  was the shortest path to restoring it.
* **Remediation.** Provenance is now mechanically verified, not declared. A
  response must name a component id registered in
  `api-contracts/openapi/v1/_common/error-component-registry.yaml` **and**
  fingerprint-match that component's canonical schema exactly. Fingerprints are
  `sha256` over canonical JSON of the response `content`, excluding
  `description`/`example(s)`/`x-*`, so prose edits do not change identity but
  any change to media types, schemas, required fields, enums, or
  `additionalProperties` does. A declaration that fails verification is fatal
  and does not fall through to the structural checks.
* **Negative controls.** NC-C3-06 (restore the boolean branch), NC-C3-10
  (unconditional bypass), plus six adversarial runtime tests (§24).
