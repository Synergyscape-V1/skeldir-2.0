## 2) Remediations Implemented

### 2.1 Metric-grade structured failure dimensions

Updated `backend/app/services/llm_validation_failures.py`:

- Normalizes and persists stable metric fields on every failure row:
  - `feature`
  - `validation_code`
  - `validation_stage`
  - `request_id` / `correlation_id` (when available)
  - `model` (default `"unknown"` when absent)
- Adds structured log dimensions (`validation_code`, `validation_stage`, `model`) for auditable event streams.

This keeps the sink canonical while improving deterministic aggregation quality without introducing non-authoritative side paths.

### 2.2 Deterministic rejection-rate computation and local alert simulation

Added `backend/app/services/llm_validation_observability.py`:

- `compute_rejection_rates(...)`:
  - deterministic SQL computation by `feature` (`endpoint`), `model`, and `[window_start, window_end)`.
  - denominator from `llm_api_calls`, rejection numerator from de-duplicated `llm_validation_failures` request IDs.
- `classify_alert_threshold(...)`:
  - deterministic threshold classifier with configurable threshold and minimum sample size.
- `simulate_alert_threshold(...)`:
  - local simulation hook to exercise alert-readiness behavior without pretending to certify a multi-day staging soak.

### 2.3 P5 proof suite and CI adjudication

Added `backend/tests/test_b16_p5_observability_readiness.py` with explicit EG coverage:

- structured failure row metric dimensions are present and queryable
- privilege fix exists in authoritative migration surface
- runtime identity can insert into sink and persisted row is readable
- rejection-rate math is correct by feature/model/window from seeded records
- threshold simulation fires for above-threshold windows and does not fire below threshold

Updated `.github/workflows/ci.yml`:

- Added `Run B1.6-P5 observability readiness gate`
- Executes `backend/tests/test_b16_p5_observability_readiness.py`
