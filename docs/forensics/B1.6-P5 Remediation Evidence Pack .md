## 2) Remediations Implemented

### 2.1 Typed sink-write isolation contract with savepoint containment

Updated `backend/app/services/llm_validation_failures.py`:

- Added `ValidationFailureSinkWriteOutcome` typed result (`recorded` vs `degraded`).
- Added `record_failure_best_effort(...)`:
  - wraps sink insert/flush in `session.begin_nested()` savepoint,
  - catches `SQLAlchemyError` for sink-write degradation,
  - returns typed degraded outcome with stable reason format: `validation_failure_sink_write_failed:<ExceptionType>`.
- Keeps strict `record_failure(...)` healthy path authoritative and unchanged for durability semantics.

This converts sink-write failure handling from implicit exception propagation to explicit, machine-testable degraded behavior while preserving healthy-path sink authority.

### 2.2 Provider-boundary integration for non-fatal telemetry degradation

Updated `backend/app/llm/provider_boundary.py`:

- Provider-boundary failure writes now use `record_failure_best_effort(...)` at canonical classification points.
- Sink-write outcomes are tracked across cache/provider validation attempts.
- Added stable metadata projection: `validation_failure_sink_status` and `validation_failure_sink_degraded_reason`.
- Extended `_finalize_failed(...)` to accept/persist `response_metadata` so degraded-audit markers are durably queryable in `llm_api_calls.response_metadata_ref`.

Result: sink-write failures no longer escape as raw request-fatal exceptions, and degraded-audit semantics are explicit in persisted machine-readable metadata.

### 2.3 Worker finalization hardening

Updated `backend/app/workers/llm.py`:

- Worker-side authority-contract exception paths now use `record_failure_best_effort(...)`.
- Added explicit degraded sink warning event (`llm_validation_failure_sink_degraded`) with tenant/request/correlation context.

This prevents sink-write failures in worker finalization exception paths from blocking terminal lifecycle transitions.

### 2.4 Non-vacuous tests for isolation and terminalization

Updated `backend/tests/test_b16_p5_observability_readiness.py`:

- Added `test_b16_p5_sink_write_failure_isolated_from_provider_failure_path`
  - forces sink-write failure,
  - proves provider validation failure path still returns typed failure (no crash),
  - asserts degraded-audit metadata persisted in `llm_api_calls`.
- Added `test_b16_p5_sink_write_failure_isolated_with_non_processing_finalization`
  - forces sink-write failure across investigation and budget flows,
  - proves non-processing finalization (`READY_FOR_REVIEW`) still occurs,
  - asserts degraded-audit metadata persisted,
  - asserts sink-row absence for forced failure requests.

### 2.5 CI adjudication update

Updated `.github/workflows/ci.yml` B1.6-P5 gate:

- Added non-vacuity grep checks for both new sink-write-failure tests.
