# B1.6-P4 Remediation Evidence Pack

Phase: `B1.6-P4 — Request-Local Regeneration Semantics + Sink Hardening`  
Status: `PASS on main`  
Date: 2026-04-01

## 1) Initial Findings (Validated on `main` Workspace State)

1. Regeneration in `provider_boundary.complete` was bounded but blind; retry attempts reused materially identical prompt context.
2. API coercion allowed legacy-shaped `llm_synthesis` dicts when `validation_state == "validated"` without authoritative contract proof.
3. Sink hardening had improved since inventory, but P4 lacked explicit adjudicative proof for:
   - correction-informed regeneration,
   - single request-local attempt cap,
   - mixed-state API fail-closed behavior,
   - invalid-synthesis topological isolation guarantees.
4. CI had B1.6-P1/P2/P3 gates but no dedicated B1.6-P4 gate.

## 2) Remediation Summary

### 2.1 Provider boundary: correction-informed regeneration + bounded budget

Updated `backend/app/llm/provider_boundary.py`:

- Added `REQUEST_LOCAL_MAX_ATTEMPTS = 3` cap and `_request_local_attempt_budget(...)`.
- Added deterministic correction payload builder:
  - `_build_validation_correction_payload(...)`
- Added deterministic attempt prompt builder:
  - `_prompt_for_attempt(...)`
- Regeneration loop now injects structured corrective context from prior validation failure into the next attempt prompt/messages.
- Enforced single request-local budget (`<=3`) for validation regeneration attempts.
- Added attempt-budget metadata to response metadata (`validation_attempts`, `validation_attempt_budget`, `validation_regeneration_active`, `validation_correction_payload`).

### 2.2 Validation spec max attempts aligned to P4 cap

Updated `backend/app/llm/output_validation.py`:

- `ProviderOutputValidationSpec.max_attempts` default increased from `2` to `3`.

### 2.3 Worker sink hardening (invalid/unvalidated text never enters success-path summary fields)

Updated `backend/app/workers/llm.py`:

- Added `_validated_summary_or_empty(...)`.
- Internal trace sinks now persist summary/provider_summary only when boundary result is `status == success` and `validation_code == success`.
- Invalid/unvalidated synthesis remains empty in internal trace success-path-like fields.

### 2.4 API fallback/coercion fail-closed hardening

Updated:
- `backend/app/api/investigations.py`
- `backend/app/api/budget.py`

Changes:

- Coercion now accepts synthesis only when:
  - lifecycle status is synthesis-eligible (`ready_for_review|approved|completed`), and
  - payload is authoritative `validated_synthesis` shape, and
  - `validation_state == validated` with required fields populated.
- Legacy/mixed payload paths are fail-closed for synthesis (deterministic data can still flow; synthesis suppressed).
- Removed synthetic fallback `llm_synthesis` construction from coercion path; fallback returns deterministic scaffold + `synthesis=None`.

### 2.5 Task retry-matrix hardening

Updated `backend/app/services/llm_dispatch.py`:

- Enqueue kwargs now default to `retry_on_failure=False` to avoid task-level retry multiplication over boundary-managed request-local regeneration.

### 2.6 CI adjudication wiring

Updated `.github/workflows/ci.yml`:

- Added explicit gate step:
  - `Run B1.6-P4 regeneration + sink hardening gate`
  - executes `backend/tests/test_b16_p4_regeneration_sink_hardening.py`
  - includes non-vacuity greps for named P4 tests.
