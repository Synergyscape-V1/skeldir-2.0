## Audit Questions

Were source rows committed? P12 includes a committed-visibility fixture that proves a separate connection observes a fit row only after commit.

Could a separate connection see them? Yes, after commit; the same fixture proves the separate connection sees zero rows before commit.

Did the worker process see them? The P12 job depends on the existing real worker/subprocess proof jobs and has its artifact validated by final P11 adjudication.

How was worker completion synchronized? P12 adds `wait_for_fit_terminal_state_sync`, which observes named terminal fit states under a monotonic deadline and emits last-observed diagnostic state on timeout.

Were arbitrary sleeps avoided? The P12 static fixture rejects `time.sleep(` in the P12 tests and harness.

What terminal state was observed? The P12 waiter observes `succeeded`, `failed`, `timeout`, `worker_lost`, `fallback_only`, or `cancelled`.

What was persisted? Fit status, fallback reason, diagnostics status, credible interval status, and artifact metadata remain persisted through B2.4 tables.

What cleanup occurred? Existing P9 cleanup and P12 artifact pruning fixtures prove cleanup/tombstone behavior without payload leakage.

How was deterministic truth proven unchanged? P12 projection tests assert deterministic-left read-only semantics and no compute/write trigger from projection.

How was tenant leakage disproven? P12 sequential tenant fixture proves distinct tenant artifact refs and projection tenant identity.

How was projection proven read-only? P12 scans projection SQL/code for deterministic-left left joins and absence of mutation/dispatch tokens.

Was a serialized payload emitted? Yes, `canonical_projection_json` emits canonical JSON from schema-bound Pydantic DTOs.

If yes, how was it sealed? DTO validators reject prompt-control syntax and unbounded/free-form string values; canonical serialization uses sorted keys and `allow_nan=False`.

How was CI enforcement proven? P12 has a required workflow job, required status context, registry entry, subsumption entry, Make target, execution manifest row, and negative-control validator.

What does P12 still not claim? P12 does not claim production-topology trust closure, live customer traffic reliability, public API readiness, TrustEnvelope completion, frontend activation, production deployment readiness, or production-scale load testing.
