# B1.5-P1 Remediation Evidence Pack

Date: 2026-03-25

## 1) Initial Findings (Pre-Remediation)

From `docs/forensics/B1.5_Context_Inventory_Report.md` and targeted code inspection:

- `investigation_jobs` had a review-friction state machine but was disconnected from active worker writes.
- `investigations` and `budget_optimization_jobs` were worker-written and used compute-only grammar (`pending/running/completed/failed`).
- Worker code could directly materialize `completed` into lifecycle-bearing tables.
- Budget domain lacked a dedicated service-owned public lifecycle authority.
- No B1.5-P1 enforcer existed to fail on lifecycle split-brain regressions.

## 2) Hypothesis Adjudication (H01-H09)

| Hypothesis | Outcome | Adjudication summary |
|---|---|---|
| H01 Investigation lifecycle split | Validated | `investigation_jobs` and worker table `investigations` were both lifecycle-capable. |
| H02 Budget lifecycle owner missing | Validated | No dedicated authority service/table owned public budget lifecycle truth. |
| H03 Worker can terminalize publicly | Validated | Worker path wrote `status="completed"` in worker-owned tables without review gating. |
| H04 Grammar inconsistent across stores | Validated | Review grammar and compute grammar were structurally divergent and both lifecycle-bearing. |
| H05 Naming alone insufficient | Validated | Without hard table/service constraints, competing stores remained claimable truth surfaces. |
| H06 Destruction/subordination absent | Validated | No enforced demotion/internal-only disposition existed for competing stores. |
| H07 Failure + review grammar not unified | Validated | Existing authority grammar lacked complete review/failure vocabulary. |
| H08 Deterministic/human control vulnerable | Validated | Worker completion could masquerade as lifecycle completion in persisted substrate. |
| H09 CI cannot prove singularity | Validated | No P1-specific enforcer/negative controls existed to detect split-brain reintroduction. |

## 3) Root Causes Confirmed

- Original LLM persistence substrate prioritized compute-job completion semantics.
- Review-friction substrate was introduced as a parallel lane rather than the only authority lane.
- Budget domain lacked an explicit service-owned authority model.
- No P1-specific CI gate encoded singular ownership + competing-store demotion rules.

## 4) Remediations Implemented

### 4.1 Canonical lifecycle grammar

- Added: `backend/app/services/centaur_lifecycle.py`
- Canonical vocabulary encoded in code:
  - `submitted`, `validating`, `investigating`, `ready_for_review`, `approved`, `rejected`, `refine_requested`, `rerun_requested`, `completed`, `failed`, `timeout`, `cancelled`.

### 4.2 Investigation authority upgrade

- Updated: `backend/app/services/investigation.py`
- `investigation_jobs` is now service-mediated with canonical grammar support and transition guards.
- Public completion requires mediated transition from `approved` -> `completed`.
- Added request-level authority linkage (`request_id`) and lifecycle/failure transition methods.

### 4.3 Budget authority introduction

- Added: `backend/app/services/budget_job.py`
- Introduced service-owned `BudgetJobService` as explicit public lifecycle owner.
- Enforces legal transitions across compute, review, and terminal states.

### 4.4 Worker write-path subordination

- Updated: `backend/app/workers/llm.py`
- Workers now:
  - Route public lifecycle transitions via `InvestigationService`/`BudgetJobService`.
  - Stop at `ready_for_review` on success (no direct public completion).
  - Record failures/timeouts through authority services.
- Worker-owned tables remain internal compute trace substrate only.

### 4.5 Persistence disposition and schema hardening

- Added migration: `alembic/versions/007_skeldir_foundation/202603251200_b15_p1_lifecycle_authority.py`
- Implemented dispositions:

| Store | Disposition | Enforcement |
|---|---|---|
| `investigation_jobs` | Public authority retained | Canonical status grammar + request-level uniqueness + transition constraints |
| `budget_jobs` | Public authority created | New authority table + RLS + grants + canonical grammar |
| `investigations` | Subordinated (internal trace only) | Compute-only statuses + internal-trace role check + authority linkage |
| `budget_optimization_jobs` | Subordinated (internal trace only) | Compute-only statuses + internal-trace role check + authority linkage |

### 4.6 ORM and parity updates

- Updated: `backend/app/models/llm.py`, `backend/app/models/__init__.py`
- Added authority model: `BudgetJob`.
- Demoted internal tables to compute-only status constraints and internal trace role constraints.

### 4.7 CI enforcement and tests
