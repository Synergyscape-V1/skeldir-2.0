# B2.4-P6 Remediation Evidence Pack

## Scope

B2.4-P6 is the real Bayesian fit worker physics bridge. It validates fit-id-only dispatch into a DB-authoritative parent worker, bounded IPC into an isolated P5 child runtime, deterministic RNG seed derivation, PyMC/PyTensor compilation, byte-capped stream draining, and bounded summary return as `sampled_unvalidated`.

This phase is mechanical, not statistical. It does not claim convergence diagnostics, production Bayesian attribution semantics, posterior artifact lifecycle, or LLM authority expansion.

## Follow-Up Findings

- The first P6 implementation incorrectly introduced worker-local result recovery through `execution_storage.py` and `result_staging.py`. That treated ephemeral Celery workers as durable state and violated the Postgres-only idempotency model.
- Stage markers were initially too loose: `model_built` could fire before the PyMC model was physically built, and `graph_compiling` did not bracket an explicit PyTensor compile operation.
- The child model needed to be a trivial physics probe so CI failures isolate IPC/compiler/runtime defects, not attribution-model complexity.
- The P6 evidence was initially written into the P5 evidence pack. The correct evidence artifact is this file.

## Remediations Made

- Removed `backend/app/bayesian/execution_storage.py` and `backend/app/bayesian/result_staging.py`.
- Removed staged-result discovery and post-DB-failure recovery from `backend/app/bayesian/fit_execution.py`.
- Reworked P6 parent IPC so input, output, and stage-marker files are created under the owned PyTensor `CompiledirLease` path.
- Added a UUID suffix to the P6 lease execution identity so a stale lease left by abrupt parent death cannot collide with broker redelivery of the same Celery task id.
- Added caller-owned lease cleanup mode to `run_supervised_sampler()` so the P6 parent can read bounded child output and then synchronously delete the full lease directory in `finally`.
- Changed DB finalization semantics: after child sampling, the parent computes only an in-memory result hash and writes the summary to PostgreSQL. If that transaction fails, the exception propagates; Celery/broker redelivery must recompute rather than loading local files.
- Tightened child stage telemetry so `model_built` follows successful PyMC model construction, and `graph_compiling` / `graph_compiled` bracket `model.compile_logp()`.
- Reduced the real-fit child model to `mu ~ Normal(0, 1)` with `observed_signal ~ Normal(mu, 1)`.
- Changed the forced child-death proof so `stage-marker-kill` emits only truthful `input_loaded` before hard termination.
- Updated tests to assert no shadow-storage modules or staged-result API remain, that the parent has no staged-result recovery path, that SIGKILL cleanup removes the lease directory, and that the child model remains a trivial physics probe.
- Updated the M0/M1 governance allowlists to recognize this P6 evidence pack as an allowed B2.4 forensics artifact, matching the existing P/P1/P2/P3/P4/P5 evidence-pack pattern.
- Updated `scripts/ci/enforce_boundary.sh` so the isolated sampler child is recognized as an explicit Bayesian boundary module for PyMC imports, matching the existing P1 import-governance allowance.
