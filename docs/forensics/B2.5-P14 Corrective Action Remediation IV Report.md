## 0. What this corrective is, in one paragraph

Two independent audits agreed the P14 issuance substrate was sound and failed
the phase on three physical counterexamples in the layers *around* it. This
corrective reproduced all three on freshly provisioned infrastructure before
changing anything, found that two of them shared a single root cause and the
third could not be repaired by extending the mechanism that failed, and replaced
each mechanism rather than each example. A `trust_access_log` guard that returned
early when no issuance-state column changed now partitions the relation's columns
totally and fences the causal witness for the whole lifecycle. A B2.7 causal
boundary implemented as a finite phrase denylist — an open-world problem a
denylist cannot decide — is now a closed derivation law: an explanation's
narrative is admissible only as the exact join of registered frame instances
filled with machine-grammar values, enforced in the application *and* in
PostgreSQL. And B2.7/B2.8 persistence, which a real `app_user` login could
fabricate end to end with no application code involved, is now bound by
referential keys and consequence guards to a durable issued TrustEnvelope and,
for a result, to the explicit request that authorized it. Every new law carries a
falsifier that has physically gone red for the predicted cause and green again
after exact restoration.

## 3. Root cause, established before remediation

### 3.1 The witness defect is a short-circuit, not a short list

`trust_access_log_issuance_authority_guard` (C16, rewritten by C17-B) computes
`consequence_changed` over the issuance state machine and its cryptographic
columns, then:

```sql
IF NOT consequence_changed THEN RETURN NEW; END IF;
```

Every protection the guard offers — terminal refusal, per-transition principal
checks, evidence correspondence — sits *after* that early return. An UPDATE that
touches only truth-bearing identity columns changes no listed consequence column,
so the guard returns before any of it runs.

The control that identifies the short-circuit rather than the column list as the
defect is the sibling relation. `trust_issuance_attempt_guard` on
`trust_issuance_attempts` has **no** early return — every UPDATE must satisfy a
legal transition — and the same probe found that relation correctly fenced under
every principal. Same phase, same author, same column-naming style; the only
structural difference is the short-circuit, and only the relation that has it is
vulnerable. That is why this corrective does not lengthen the column list.

### 3.2 A post-terminal-only fence would have left the class open

The obvious repair — fence the witness once `issuance_state` is terminal — was
tested against the causal graph and rejected. The Gate 0 consequence guard
requires a terminal row to *agree* with its ledger row field by field. A witness
column rewritten while the ledger is still `authorized` is therefore projected
faithfully into terminal history, and the durable record then records a witness
that was already falsified. Fencing from INSERT is both the narrower repair and
the total one. It is measured directly by
`test_p14_r4_the_witness_is_immutable_before_terminalization_too`.

### 3.3 The B2.7 boundary was solving an undecidable problem

`_CAUSAL_LANGUAGE` is a finite regular expression over causal indicators. The
property it is asked to decide is "this English text does not assert causation",
whose complement is unbounded. No finite extension closes it; the twenty
accepted sentences and the next twenty would differ. The mechanism had to be
replaced, not extended — which is exactly what directive §11.2 requires.

### 3.4 B2.8/B2.7 persistence expressed existence, not consequence

`request_id uuid NOT NULL REFERENCES b28_simulation_requests(id)` proves a row
exists. The relation that had to hold is:

```text
row is a genuine consequence of
  (explicit request) ∧ (tenant-valid source Trust) ∧
  (admissible policy authority) ∧ (governed solver)
```

None of those conjuncts was represented physically. This is the Gate 0 defect
class applied to P14's own relations.

## 4. Remediation

One migration (`202609051200`), one new application module, and narrow edits to
the B2.7 contract/renderer/adjudicator.

### 4.1 Terminal provenance conservation (Exit Gate 1)

A second, independently severable trigger,
`trg_trust_access_log_witness_immutability`, partitions the relation's columns
*totally* by iterating `to_jsonb(NEW)` rather than naming columns:

| class | columns | rule |
|---|---|---|
| operational metadata | `replay_count`, `last_replayed_at`, `updated_at` | freely writable by any UPDATE holder |
| governed issuance machine | the twelve columns C16/C17-B adjudicates | deferred to that guard |
| **immutable causal witness** | everything else, **including any column a future migration adds** | refused, `42501 trust_access_log_witness_immutable:<column>` |

The default is the fence. A column added later and never classified is immutable
at runtime and a failing assertion in
`test_p14_r4_the_witness_partition_covers_every_access_log_column`, so the
classification decision is made deliberately instead of by omission.

Lawful behaviour is preserved exactly, and measured:
`_upsert_access_log`'s replay path (`ON CONFLICT DO UPDATE SET replay_count =
replay_count + 1, last_replayed_at, updated_at`) is the only UPDATE the API
principal performs on this relation, and every issuer/signer UPDATE in
`app/trust/audit.py` writes issuance-machine columns alone. Directive §11.3's
instruction not to solve Gate C by revoking UPDATE is honoured by construction:
nothing is revoked.

### 4.2 Open-world causal conservation (Exit Gate 2)

`backend/app/explanation/templates.py` inverts the quantifier:

```text
before:  admissible(text)  iff  text contains no listed causal phrase
now:     admissible(text)  iff  text == compose_narrative(
                                    [render(frame(claim), value_text(claim))
                                     for claim in conserved_claims])
```

Three properties make this conservation rather than a bigger filter:

1. **The frame corpus is closed and content-addressed.** Twenty frames, hashed
   into `EXPLANATION_TEMPLATE_REGISTRY_HASH =
   sha256:45a4c69e…b90cb397`, mirrored row-for-row into
   `b27_narrative_templates`. Adding a frame is a migration.
2. **The one variable slot carries a machine grammar.** Seven grammars —
   `opaque_id`, `hash`, `enum`, `currency`, `integer`, `money_minor`, `boolean` —
   and none of them matches a space-separated English phrase. This closes the
   smuggling channel the templated design would otherwise open, which is
   OW-R4-3 below.
3. **The narrative is the join, exactly.** Byte equality. There is no prefix,
   suffix or interstitial position where an unregistered sentence can live.

The corpus itself is adjudicated at load (`assert_registry_admissible`): no
frame may carry a causal claim kind, assert a causal relation, carry a numeral
of its own, or open more than one variable position. That is where a finite
lexical check is the right instrument — over a closed, human-reviewed set of
twenty, at merge time — rather than the wrong one.

The pre-existing `_CAUSAL_LANGUAGE` sweep is retained as a second,
independently severable layer. It is no longer the boundary.

### 4.3 Consequence-bound downstream persistence (Exit Gate 3)

Following the shape Gate 0 already proved:

* **Referential binding.** `b27_explanation_materializations` and
  `b28_simulation_requests` gain a `NOT NULL source_issuance_envelope_hash` with
  a real foreign key to `trust_envelope_issuance_log (tenant_id,
  envelope_hash)`. A downstream artifact that names no durable issuance is
  unrepresentable, and stays unrepresentable if a trigger is dropped.
* **Consequence guards.** BEFORE INSERT triggers require: agreement with the
  bound terminal row (tenant, subject, semantic truth, policy state); admission
  policy for a simulation request (`read_only`/`blocked` sources refused);
  field-by-field agreement between a result and its request; the *derivation* of
  `action_authority` from the source policy rather than its assertion; the
  governed solver profile and sufficiency policy version; and allocation
  agreement between a proposal and its result.
* **Physical narrative derivation.** The B2.7 guard re-derives every claim's
  rendering from `b27_narrative_templates` and the claim's `value_text`,
  requires the value to match the frame's grammar, and requires the stored
  narrative to equal the exact join. Free prose is unrepresentable at the
  database tier, not merely unproduced by the application.
* **Append-only.** UPDATE/DELETE fences on all four downstream relations,
  admitting exactly one transition: the definer-authority staleness marking on
  `b27_explanation_materializations`, which is additionally one-way (a stale
  explanation cannot be revived).

No runtime principal holds INSERT, UPDATE or DELETE on either frame-registry
relation; `SELECT` only, because the guard runs with the writer's own authority
and must be able to read the corpus it is checked against.

## 7. Compositional lineage (Exit Gate 4)

`test_p14_r4_one_real_signed_state_conducts_into_b27_and_b28` drives one state:

```text
fresh Ed25519 keypair (generated at test time)
  -> real prepare_payload_for_signing + canonicalize_signature_material
  -> real signature
  -> real verify_trust_envelope (public key only)  = verified
  -> app_user authorizes the ledger row
  -> app_trust_issuer opens the attempt
  -> app_trust_signer persists the signature consequence (64 raw bytes,
     signed_envelope jsonb)
  -> app_trust_issuer completes signature_known -> issued and projects
     exactly one durable terminal row through the P14 Gate 0 guard
  -> app_user READS THE RETAINED ARTIFACT BACK OUT OF trust_access_log
  -> re-verified against the public key
  -> real compose_explanation on those bytes
  -> materialization persisted, FK-bound to the terminal row
  -> real simulate_from_trust on those bytes with an explicit request
  -> request / result / proposal persisted, each consequence-bound
```

The lineage is then reconstructed *by query*, not from fixture variables: a
single join across `trust_envelope_issuance_log`, `trust_access_log`,
`trust_issuance_attempts`, `b27_explanation_materializations`,
`b28_simulation_requests`, `b28_simulation_results` and `b28_proposals` returns
exactly one row in which `envelope_hash` and `semantic_truth_hash` are identical
across every relation and the action authority agrees between result and
proposal.

**Falsifier**: substituting a different real issuance identity is refused with
`b28_request_source_trust_mismatch`; naming a semantic truth no issuance carries
is refused with `b28_request_requires_durable_issuance`.

**Declared bound, not credited.** The upstream legs — signed commerce ingress
through B2.3 match verdicts and a real B2.4 Bayesian fit — are proved by the
C19/C9 lanes and were not re-driven here. This suite proves conduction from the
cryptographic issuance boundary onward, which is the segment P14 owns. No
governed statistical-worker execution physics were touched by this corrective:
no cores, threads, chains, processes or numerical-library parallelism were
changed anywhere in the tree.

Recorded as limitations, not converted into acceptance.

1. **Upstream compositional legs are inherited, not re-driven.** The B2.3 →
   B2.4 → Trust legs are proved by the C19/C9 lanes on the same tree; this
   corrective proves conduction from the cryptographic issuance boundary onward.
   A full nine-process journey remains the strongest available evidence for Exit
   Gate 4 and is not claimed here.
2. **No HTTP/product ingress exists for B2.7/B2.8 in this phase.** The proofs
   are runtime-boundary proofs. `CONTRACT SAFETY PROVEN` is not used as evidence
   for `PRODUCTION CONSUMER WIRING PROVEN`.
3. **Solver execution is bound, not recomputed, at the database tier.** The
   guard proves a result is the consequence of an admitted request over real
   Trust, agrees field-by-field with it, names the governed solver profile and
   conserves the budget. It does not re-run the solver in SQL. The "the solver
   actually ran" conjunct is proved at the application boundary by the measured
   invocation counter (Gate G), not at the database.
4. **The projection-profile loader still caches per process** (audit 68's OW-3).
   A restrictive registry edit requires process replacement to take effect.
   Stored artifacts bind to the profile hash, so this is a staleness surface in
   time rather than an authority escape; it is unchanged by this corrective and
   remains governance debt.
5. **Frame-corpus expressiveness is a product constraint.** An explanation can
   now say only what a registered frame can state. That is the intended
   trade — and `test_b27_r4_every_gate5_state_still_renders_a_lawful_explanation`
   exists so the safety property cannot be bought by making the product mute —
   but a future surface needing new prose needs a migration, by design.
