# B2.3-P6 Remediation Evidence Pack

## Scope

Phase B2.3-P6 closes Revenue Verification and Matching by proving the composed production path:

```text
signed webhook -> verified commerce identity -> deterministic batch match
-> matched_provisional verdict -> match detail API -> production transition
-> matched_confirmed verdict -> attribution substrate join
```

This pack is bounded to B2.3-P6. It does not implement Bayesian diagnostics, B2.6 reconciliation workflow, vendor normalization, dashboards, frontend product UI, LLM explanation, or downstream reporting.

## Initial Findings

| Hypothesis | Finding | Remediation |
| --- | --- | --- |
| P6-FH01/P6-FH02 | P0-P5 proved components, but there was no P6-governed real DB signed-webhook-to-verdict-to-API closure proof. | Added `backend/tests/test_b23_p6_end_to_end_closure.py` with valid Shopify HMAC ingress, invalid signature rejection, duplicate idempotency, production batch matching, API reads, tenant negative control, production transition callable, and post-transition API consistency. |
| P6-FH04 | Transition proof needed database-observable persisted timestamp eligibility, not Python time mocking. | P6 runtime test verifies unchanged timestamps remain provisional, then persists timestamps older than `PROVISIONAL_MATCH_WINDOW` before invoking `transition_stale_provisional_to_confirmed`. |
| P6-FH06/P6-FH07 | Matched verdicts could be represented without a durable attribution FK at the database boundary. | Added a `NOT VALID` Postgres check constraint enforcing non-null `attribution_event_id` for `matched_provisional`, `matched_confirmed`, and `adjusted` states. `NOT VALID` preserves deployability over existing historical rows while enforcing new/updated rows. |
| P6-FH08/P6-FH09 | `VERIFICATION_COVERAGE` was not present as a governed deterministic primitive with connected-platform denominator semantics. | Added `docs/specs/b23_p6_verification_coverage.md` and `app.revenue_verification.verification_coverage` with exact decimal compute semantics. |
| P6-FH10 | Exception base-table proof needed to be part of P6 closure. | Added information-schema runtime test requiring `b23_exception_records = BASE TABLE`. |
| P6-FH11 | P0-P5 preservation had to survive the new matched-state FK law. | Updated P2/P3/P4 runtime fixtures so matched rows carry attribution FKs while pending/unmatched null-FK semantics remain valid. |
| P6-FH12/P6-FH13 | Downstream readiness needed bounded consumption contracts without B2.4/B2.6 overreach. | Added `docs/readiness/b23_downstream_readiness.md` with B2.4/B2.6 consumable surfaces, exclusions, and deferral register. |
| P6-FH14 | P6 needed to join the merge-blocking composite proof surface. | Extended the `B2.3 Composite Proof Harness` CI job with P6 runtime and governance enforcement. |
