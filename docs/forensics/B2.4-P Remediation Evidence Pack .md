# B2.4-P Remediation Evidence Pack

## Scope

This evidence pack covers B2.4-P1 only: authority schema, RLS/GUC isolation, module transition, table/index/constraint safety, and CI validation. It does not claim Bayesian fitting, source snapshot computation, planner/runtime harness, diagnostics computation, confidence projection, frontend semantics, artifact pruning, public Trust API exposure, or LLM behavior.

## Initial Findings

- `backend/app/bayesian/` was absent.
- `bayesian_model_fits` and `bayesian_artifacts` were absent from migrations, ORM metadata, and canonical schema authority.
- No Bayesian RLS/GUC policies existed because the tables did not exist.
- M5/M7 validators still encoded pre-implementation readiness assumptions and needed to allow a legitimate P1 implementation.
- B2.4 dry-run CI did not yet enforce P1 table, RLS, hash, index, and module-boundary invariants.
- Local Docker was unavailable, so empirical DB proof used local PostgreSQL directly.

## Remediations

- Added canonical internal package `backend/app/bayesian/` with enums, exceptions, SQLAlchemy models, repository stubs, artifact repository stubs, and schema metadata.
- Added Alembic migration `202605201200_b24_p1_authority_schema.py`.
- Added `bayesian_model_fits` and `bayesian_artifacts` with tenant FKs, artifact FK, bounded hashes, numeric checks, state checks, artifact reference checks, and source-window ordering.
- Enabled and forced RLS on both tables with policies tied to `app.current_tenant_id`.
- Added tenant and composite indexes for tenant lookup, source hash lookup, status lookup, model/window lookup, eligibility lookup, fallback lookup, artifact fit lookup, artifact ref lookup, and artifact hash lookup.
- Updated canonical SQL/YAML schema authority and exported ORM models.
- Converted M5/M7 validators from absence blocking to P1-aware validation and kept M6 no-LLM import enforcement active.
- Added `scripts/ci/validate_b24_p1_authority_schema.py` and wired it into Makefile, enforcer registry, gate matrix, and the B2.4 gate dry-run workflow.
- Added static and PostgreSQL-backed tests proving non-vacuous failure modes.

## DB Proof

- Database: local PostgreSQL `skeldir_b24_p1_local`
- Migration authority role: `migration_owner`
- Runtime role: `app_user`
- RLS proof: tenant B cannot read tenant A rows; missing tenant GUC returns no rows.
- Constraint proof: invalid status, invalid artifact type, invalid storage backend, negative numeric values, invalid source-window ordering, and invalid hashes fail.
- Hash proof: 63-character, 65-character, non-hex, and uppercase hash values fail; lowercase 64-character SHA-256 hex values succeed.
- Index proof: `pg_indexes` inspection confirms required tenant-scoped indexes; representative `EXPLAIN` plans under RLS use the expected indexes.

## Migration Safety

- No existing deterministic ingress or B2.3 hot tables are altered.
- FK locks involve new B2.4 tables and the existing `tenants` table only.
- Indexes are regular transactional indexes on newly created empty tables.
- No `CREATE INDEX CONCURRENTLY` or `postgresql_concurrently=True` appears.
- No native PostgreSQL enum DDL appears.
