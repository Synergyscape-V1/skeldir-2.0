- New relation `b26_p2_ingress_auth_witness` (PK = ingress id): random
  per-ingress witness token. **No runtime principal holds INSERT**

  `b26_p2_record_ingress_auth_witness()` (SECURITY DEFINER, EXECUTE

  ingress; NULL-fail-closed throughout).
- `b26_p2_attest_provenance_evidence` rewritten: caller allowlist is
  (`app_ingress`, `migration_owner`, `postgres`) — **`app_user` revoked**;
  promotion additionally requires an existing witness row
  (`b26_p2_evidence_witness_missing` otherwise); the witness hash is
  recorded into `provenance_evidence.evidence_witness_hash`.
- Ingress provenance trigger requires **witness-backed** evidence for
  `unknown → known` (bare writes and witnessless echoes refuse).
- No raw secret retention: the witness is fresh randomness folded
  through sha256, a capability — never provider secret material.
- API path (`backend/app/ingestion/event_service.py`): HMAC-verified
  arrivals persist through the dedicated ingress credential
  (`B26_P2_INGRESS_DATABASE_URL`; witness + signed-re-ingestion

  same way. Without a mounted ingress DSN the authorship refusal

  `B26_P2_INGRESS_DATABASE_URL` by `setup-postgres-ci`). No membership

  relabeled): strict allowlists apply where the ingress principal
