This iteration supersedes the 2026-08-02 corrective pack. In particular, the

## 1. Initial findings and root causes

Investigation from the corrective baseline confirmed eight load-bearing root
causes:

1. Admission allowed 50 exact references while evaluation and output stopped at
   two, silently discarding accepted work.
2. Admission, evaluation, output, signing, audit, and serialization cardinality
   were treated as one limit despite having different capacities.
3. The response could not represent incomplete work or prove conservation.
4. Aggregate byte limits bounded returned bytes but could not detect omitted
   matches.
5. CI checked upper bounds without proving accepted-work conservation.
6. Any continuation retrofit risked becoming tenant-history traversal instead
   of continuation over the caller's exact reference sequence.
7. Progress coupled to returned matches could stall forever on nonmatches.
8. Repeated YAML parsing in the P2 hash/canonicalization path made the maximum
   production request take roughly 65 seconds, while request bodies were read
   only after full ASGI buffering and tenant-context audit failure had no finite
   end-to-end deadline.

## 3. Selected external contract: Outcome A

The permissible design is continuation over the normalized exact-reference
input sequence. The endpoint remains an exact-reference lookup, not a general
search, tenant-history scan, compute job, export, artifact traversal, or LLM
surface. The caller cannot choose page size, offset, cursor position, policy,
schema version, or temporal traversal depth.

## 4. Work-conservation contract

Every successful page carries:

```text
accepted_count = original normalized exact-reference count (1..50)
evaluated_count = cumulative stable-sequence position
page_evaluated_count = refs evaluated on this page (1..2)
remaining_count = accepted_count - evaluated_count
complete = (remaining_count == 0)
```

The Pydantic model rejects any violation of
`evaluated_count + remaining_count == accepted_count`. Nonterminal pages must
have a continuation token; terminal pages must not. The OpenAPI 1.2.0 contract
requires the same shape.

## 5. Cursor authority and privacy

The opaque `p10c1` cursor is a deterministic canonical JSON claim set signed
with Ed25519 in the explicit domain
`skeldir:b25-p10:query-continuation:v1\0`. Claims contain only version, key ID,
request-binding hash, next position, total accepted count, and root expiry.
The binding covers tenant hash, ordered subject types, ordered exact refs, and
both normalized temporal predicates. It contains no raw tenant or reference.

Verification uses public material only and rejects malformed/non-canonical
Base64url, wrong version/key/signature, tampering, cross-tenant reuse,
cross-request reuse, predicate changes, total/position drift, and expiry before
the source adapter is called. Retry of the same page produces the same next
token and audit identity.

## 6. Stable ordering and nonmatch progress

The page slice is `subject_refs[start_position:end_position]`. SQL results are
mapped by verdict UUID and envelopes are emitted by iterating that slice, so DB
ordering cannot reorder the response. `end_position` advances over all page
refs, including absent or temporally nonmatching refs. Audit idempotency binds
the full request hash and stable global position.

## 7. Exact-reference database physics

The real PostgreSQL proof seeds 5,002 verdict rows, asks for two exact verdict
UUIDs, and runs production-equivalent `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`.
It then adds 5,000 unrelated rows, analyzes the table, and repeats the identical
plan. The proof requires at most two rows, no `Seq Scan`, no `OFFSET`, execution
under one second, and no more than 32 additional shared hit/read blocks after
almost doubling history. Because Outcome A never walks tenant history, a new
composite temporal traversal index is correctly N/A.

## 8. Count and byte ceilings

```text
query request body                       65,536 bytes
verify request body                     262,144 bytes
accepted exact references                    50
evaluated references/page                     2
returned envelopes/page                       2
signature operations/page                      2
issuance audit effects/page                    2
concurrent query executions/worker             2
individual serialized envelope            65,536 bytes
aggregate response                    4,194,304 bytes
cursor token                                2,048 bytes
```

The original response ceilings are preserved; capacity was not raised to hide
the defect.

## 9. Streaming ingress enforcement

Both POST endpoints reject an invalid, negative, or over-limit declared
Content-Length before parsing or downstream dependencies. Without a length, or
with a false small length, the reader processes/retains at most limit+1 and
stops. Exact-limit bodies are accepted; limit+1 bodies are typed 413. Nonidentity
Content-Encoding is typed 415 before body consumption, so compressed payloads
cannot bypass the uncompressed authority boundary. Malformed JSON below the
limit remains typed 422.

Endpoint spies prove oversized query input never opens the DB and oversized
verification never authenticates, loads keys, or invokes cryptography.

## 10. Tenant-context audit liveness

The missing/mismatched transaction-tenant handler preserves the existing
sanitized 503 response and now has finite internal budgets:

```text
audit connection acquisition         250 ms
audit insert plus commit              750 ms
emergency telemetry attempt           250 ms
total handler                        1500 ms
handler in-flight slots                  16
emergency signal buffer                 256
```

The P7 request remains access-log-only and commits in its own session. Tests
inject a stalled acquisition, stalled audit, stalled handler, failed writer,
and stalled telemetry transport. Every path returns within its governed bound.

## 11. Truthful audit outcome and emergency path

`request.state.tenant_context_audit_outcome` is `durable_committed` only after
commit succeeds and `emergency_only` otherwise. Emergency material contains
only tenant/client/correlation hashes plus bounded route/stage labels. It is
placed immediately in a bounded deque and a bounded CRITICAL logging attempt is
made; logging failure cannot extend the handler deadline or leak raw identity.

## 12. Latency root cause and remediation

Profiling identified repeated parsing of immutable deploy-time YAML manifests
inside every semantic/signature hash projection. One envelope caused roughly
200 manifest reads and millions of YAML parser calls. The manifest, compiled
field-domain map, array-ordering map, and two version registries are now cached
once per worker with bounded `lru_cache` entries. Contract semantics and all P2
negative controls remain unchanged.
