## 1. Scope and initial findings

The follow-up investigation began from `origin/main` at
`c18b2acdcd08b814d5d827bee196e4df710e0693`. The previous P10 surface was
substantive but not context-robust. Three root causes were confirmed:

1. Query time filters were applied to newly issued envelope `created_at`, so
   request time—not persisted source chronology—decided whether historical
   evidence matched.
2. The public taxonomy contained five subject types while P5 had one complete
   adapter (`match_verdict`); unsupported types could be interpreted as false
   absence.
3. CI enforced four structural mutations but did not falsify semantic time,
   adapter parity, egress physics, tenant failure, wire bytes, rollback
   durability, timezone, nonce, or transitive compute reachability.

Additional confirmed gaps were an open 250-pair expansion, no returned/signing/
audit/serialized-byte closure, no post-auth principal/header/GUC equality
assertion, no canonical durable handler for missing tenant context, verify
projection bypass of the response guard, and runtime nonce acceptance outside
the OpenAPI range.

## 3. Authoritative chronology and boundary semantics

The only accepted temporal authority is persisted
`public.b23_match_verdicts.updated_at`. Both bounds are inclusive. Aware input
timestamps are normalized to UTC. The database query orders by
`updated_at ASC, id ASC`, accepts exact verdict URNs only, binds a UUID array,
and applies `LIMIT :row_limit` before build, audit, signing, or serialization.
There is no fallback to request time, envelope issuance time, deep `OFFSET`, or
fetch-all-before-limit path.

## 5. Query and pagination semantics

The request accepts 1–5 unique subject types and 1–50 unique exact references,
but the normalized product may not exceed 50. Wildcards, regex-like tokens,
caller policy/schema authority, caller page size, cursor depth, and offset are
not accepted. This exact-reference endpoint has no continuation cursor: it
returns the first two authoritative rows in deterministic chronology order.

## 9. Tenant-context exception and registered handler

After machine authentication, P10 compares authenticated tenant, parsed
`X-Tenant-ID`, transaction-local `app.current_tenant_id`, and the current
role's `rolbypassrls`. Any missing, invalid, unequal, or bypass context raises
`TenantContextMissingException`. `app.main` registers the handler. The client
always receives sanitized 503 `tenant_context_unavailable`; raw SQL, GUC,
tenant, client, and exception details never enter the response.

## 10. Durable tenant-security audit

The handler writes a PII-free `scope_denial` event with stable reason
`tenant_context_missing` through P7's autonomous session. Evidence binds the
trusted tenant hash, machine-client hash, correlation identity, method, route
template, and failure stage. A separate observer sees the row after caller
rollback. If that writer fails, the request remains 503 and a structured
CRITICAL signal is emitted independently.

## 11. Pool reuse and tenant isolation

The real-pool proof covers Tenant A commit, unbound checkout, Tenant B rollback,
unbound checkout, Tenant A again, concurrent A/B traffic, cancellation, and a
final unbound checkout. It proves transaction-local assignment and cleanup
after commit, rollback, and cancellation with no session-global residue.

## 12. Wire signature and JWKS proof

The client-visible HTTP bytes—not the pre-serialization object—are parsed and
verified with a public-only registry reconstructed from JWKS fetched through
the mounted key endpoint. Mutation of a signed field in those bytes is
rejected. The private seed and private key never appear in JWKS or responses.

## 13. Verify projection privacy

`/verify` is body-bounded before authentication/key lookup/crypto, requires the
P9 verify scope and tenant-context assertion, and recursively guards both
verified and rejected external projections. Raw tenant/client/user IDs,
credentials, private material, SQL/GUC/trace data, provider payloads, and
authoritative float money are rejected.

## 14. Audit, replay, quota, and time physics

Issuance audit commits independently before a success is returned. P9 nonce
and rate state use autonomous commits. A controllable fixed-window clock proves
exact L+L admission across the boundary. UTC/Chicago/Tokyo sessions persist
identical epochs using native aware datetimes. Builder, signing, audit, and
serialization failure labels each prove consumed quota survives downstream
rollback. The approximately 2x boundary burst is an explicit design property,
and the governed limits are sized for it.

## 15. Nonce contract

Both FastAPI/OpenAPI and machine authentication require 16–256 characters.
Fifteen- and 257-character controls are rejected before request-identity hash,
nonce insert, or rate state. The P9 valid fixtures were updated to remain
within the canonical contract.

## 16. Runtime key convergence

Runtime signing authority comes only from the deployment secret seed, governed
key ID, and UTC validity timestamp. Two fresh processes generated identical
JWKS for the same authority. Missing, malformed, or inconsistent authority
fails request handling closed. P8 proves retired keys cannot sign net-new
envelopes while eligible historical signatures remain verifiable.

## 17. No-compute/no-LLM proof

P10 does not call LLM, Bayesian, Celery, task, artifact, export, or autonomous
action paths. The validator recursively resolves every reachable local import
from the route and rejects forbidden modules plus `delay`, `apply_async`, and
`create_task`. NC-P10-19 mutates the production route with a reachable task
import and fails non-zero.
